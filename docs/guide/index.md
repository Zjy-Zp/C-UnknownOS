# 指南总览

本指南面向第一次接触 cunos 的读者，目标是让你在两小时内完成"环境搭好 → 编译通过 → QEMU 里看到内核输出"的完整闭环。

## 前置知识

不需要写过操作系统，但以下内容会显著降低学习成本：

- **x86 汇编基础**：知道 `mov` / `jmp` / `lgdt` 在做什么就够了，其余边做边查。
- **C 语言指针与位运算**：内核里大量使用位域、指针强转、位图。
- **链接与内存布局**：理解 `.text` / `.data` / `.bss` 段的含义，以及链接脚本在干什么。

## 推荐顺序

1. [五分钟跑起来](./getting-started) —— 最小可启动镜像
2. [工具链与交叉编译](./toolchain) —— 装好 i686-elf 工具链，理解为什么必须交叉编译
3. [QEMU 无头验证](./qemu-verify) —— 无图形界面下的启动验证与日志抓取

## 环境矩阵

| 环节 | 推荐环境 | 说明 |
|---|---|---|
| 编译 | WSL2 Debian / 原生 Linux | 交叉工具链在 Windows 原生环境下易踩坑，建议放 WSL |
| 运行 | Windows 侧 QEMU | 与编译环境分离，`-nographic` 无头启动 |
| 调试 | `gdb-multiarch` + `-s -S` | 断点、寄存器、内存全可查 |
| 版本管理 | Git | 内核改动频繁，建议每次可启动状态打 tag |

::: warning 不要把编译环境放在 Windows 原生侧
Windows 下的 `gcc` 行为、路径分隔符、链接器脚本解析都与 Linux 有细微差异，这些问题在"编译通过但启动黑屏"时极难定位。统一放在 WSL 里，省掉 80% 的玄学问题。
:::
