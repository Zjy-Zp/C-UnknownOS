# 帧缓冲与图形桌面

## 两条路径

| 方式 | 获取分辨率的途径 | 适用阶段 |
|---|---|---|
| VBE（VESA BIOS Extension） | 实模式下 `int 0x10, AX=0x4F02` | 引导阶段建立帧缓冲 |
| 直接操作显存 | 已知物理地址（如 `0xFD000000`） | 保护模式下绘制 |

VBE 必须在**实模式**下调用（BIOS 中断只在实模式可用），所以流程是：引导时先问出模式信息，把帧缓冲物理地址、宽、高、bpp 存到内核能读到的地方，然后才切保护模式。

```c
typedef struct {
    uint64_t fb_addr;
    uint32_t width;
    uint32_t height;
    uint32_t pitch;      // 每行字节数，可能 > width * bpp/8
    uint8_t  bpp;
} video_info_t;
```

::: warning `pitch` 不等于 `width * 4`
显卡可能按固定步长（如 2048 字节）对齐每一行。用 `width * 4` 当作行跨度，画面会从第二行开始整体斜切。绘制时一律用 `pitch` 推进行指针。
:::

## 像素写入

```c
static inline void put_pixel(video_info_t *vi, int x, int y, uint32_t rgb) {
    uint8_t *row = (uint8_t *)vi->fb_addr + y * vi->pitch;
    *(uint32_t *)(row + x * (vi->bpp / 8)) = rgb;
}
```

这是所有绘制的原点：矩形、直线、位图、字体渲染最终都归到这里。优化手段（双缓冲、脏矩形、批量填充）都建立在它之上。

## 最小绘制能力

按实现顺序：

1. **清屏** —— 一次性 memset 整个帧缓冲
2. **填充矩形** —— 按行写入，比逐像素快一个数量级
3. **位图字体** —— 内嵌 8×16 字形点阵，每个字符逐位展开
4. **直线与圆** —— Bresenham 算法
5. **双缓冲** —— 在内存画布上合成，最后一次性拷贝到显存，消除闪烁

## 桌面与窗口

桌面管理器的最小结构：

| 组件 | 职责 |
|---|---|
| 窗口树 | 记录窗口位置、尺寸、Z 序、可见性 |
| 合成器 | 按 Z 序从底到顶合成各窗口画面 |
| 输入分发 | 鼠标先做命中测试，决定事件归属哪个窗口 |
| 光标 | 单独一层，永远最上 |

鼠标需要 PS/2 或 USB 输入驱动提供位移量。位移是**相对**的，需要维护一个软件光标坐标并做边界钳制。

## 性能现实

帧缓冲在内存里，但写满一块 1024×768×32bpp 的区域就是 3 MiB 的内存写入。如果每帧全量重绘，在真实硬件上会明显卡顿。

优化优先级：

1. 只在内容变化时重绘脏区域
2. 大块填充用 `rep stosd` 而不是逐像素循环
3. 光标移动只重绘旧位置和新位置两小块
