# 中断、异常与系统调用

## 三者的区别

| 类型 | 来源 | 同步性 | 典型例子 |
|---|---|---|---|
| 异常 | CPU 内部 | 同步（指令引发） | 除零、缺页、无效操作码 |
| 硬件中断 | 外部设备 | 异步 | 键盘、定时器、磁盘完成 |
| 系统调用 | 软件主动 | 同步 | `int 0x80` 陷入内核 |

三者统一通过 **IDT（中断描述符表）** 分发。i386 的 IDT 有 256 个表项，每项 8 字节。

## IDT 表项结构

| 位段 | 含义 |
|---|---|
| 15–0 | 处理函数地址低 16 位 |
| 31–16 | 代码段选择子（通常是 `0x08`） |
| 39–32 | 保留 |
| 47–40 | 类型与属性（`0x8E` = 32 位中断门，ring 0） |
| 63–48 | 处理函数地址高 16 位 |

加载方式与 GDT 相同：构造 `idtr`（6 字节：2 字节 limit + 4 字节 base），执行 `lidt`。

## 常见异常向量

| 向量 | 名称 | 触发原因 |
|---|---|---|
| 0 | 除零 | `div` 除数为 0 |
| 6 | 无效操作码 | 执行了未定义指令 |
| 8 | 双重故障 | 处理异常时又发生异常 |
| 13 | 通用保护故障 | 段权限违规、越界 |
| 14 | 缺页 | 访问未映射或权限不足的页（`CR2` 存出错地址） |

::: danger 8 号双重故障没有返回地址
双重故障的压栈现场与普通异常不同，很多情况下没有可靠的返回地址。如果它又导致三重故障，CPU 会直接重启。因此处理双重故障的函数应尽可能"只打印、不依赖栈内容"，并且绝不能再触发任何异常。
:::

## 硬件中断

外部中断经 **PIC（8259A）** 或 **APIC** 送达 CPU。传统 PIC 需要重映射，因为默认向量与 CPU 异常冲突：

```c
outb(0x20, 0x11); outb(0xA0, 0x11);   // ICW1：级联、需要 ICW4
outb(0x21, 0x20); outb(0xA1, 0x28);   // ICW2：主片→0x20，从片→0x28
outb(0x21, 0x04); outb(0xA1, 0x02);   // ICW3：级联线
outb(0x21, 0x01); outb(0xA1, 0x01);   // ICW4：8086 模式
outb(0x21, 0x00); outb(0xA1, 0x00);   // 打开全部屏蔽位
```

重映射后，IRQ0–7 → 向量 `0x20`–`0x27`，IRQ8–15 → `0x28`–`0x2F`。

**中断服务例程必须发 EOI**，否则该 IRQ 不再触发：

```c
outb(0x20, 0x20);                        // 主片
if (irq >= 8) outb(0xA0, 0x20);          // 从片
```

## 系统调用

`int 0x80` 是 i386 的传统入口。用户态通过寄存器传参：

| 寄存器 | 用途 |
|---|---|
| `eax` | 系统调用号 |
| `ebx` `ecx` `edx` `esi` `edi` `ebp` | 参数 1–6 |
| 返回值 | `eax` |

陷阱门（类型 `0xEF`）与中断门的差别：陷阱门进入时不自动清 `IF`，允许在系统调用期间继续响应硬件中断。

## i386 ABI 兼容层

要让既有 Linux i386 程序在 cunos 上跑，需要对齐三件事：

1. **调用约定**：参数寄存器与返回值位置完全一致
2. **系统调用号**：与 Linux i386 的编号表一致（如 `exit=1`、`write=4`、`brk=45`）
3. **用户态可观测语义**：文件描述符从 3 开始、`errno` 通过返回值取负传递

结构体布局与 `struct stat` 之类的尺寸也必须逐字节对齐，否则程序能启动但会在某个 `ioctl` 上诡异失败。
