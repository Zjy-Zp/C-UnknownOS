# 内核架构总览

cunos 按"能独立验证的最小层"切分。每一层都有明确的输入契约、输出契约与可观测验证点。

## 分层视图

```
┌─────────────────────────────────────────────┐
│  用户态程序 / 内核内图形桌面                  │
├─────────────────────────────────────────────┤
│  i386 ABI 兼容层（Linux 系统调用语义）        │
├─────────────────────────────────────────────┤
│  VFS │ 网络栈 │ 图形子系统                    │
├─────────────────────────────────────────────┤
│  驱动：PCI / ATA / AHCI / USB / 输入 / 显示   │
├─────────────────────────────────────────────┤
│  中断与异常 │ 调度 │ 定时器                    │
├─────────────────────────────────────────────┤
│  分页与物理内存管理                            │
├─────────────────────────────────────────────┤
│  引导：实模式 → 保护模式                       │
└─────────────────────────────────────────────┘
```

自顶向下依赖，自底向上构建。任何一层不允许反向调用上层。

## 子项目与职责

| 子项目 | 职责 | 关键验证点 |
|---|---|---|
| 引导 | 从 BIOS 交权到内核入口 | 串口打印内核版本横幅 |
| 内存 | 物理页分配、虚拟地址映射、内核堆 | 可分配/释放 4K 页并读回写入值 |
| 中断 | IDT、异常处理、IRQ 分发、系统调用门 | 主动触发 `int 3` 能被正确捕获 |
| 驱动 | 设备枚举与访问 | `lspci` 等价输出、磁盘读写校验 |
| VFS | 统一文件接口、挂载点 | 挂载后可按路径打开读取 |
| 网络 | 协议栈 | 收发包、ICMP 回显 |
| 图形 | 帧缓冲、绘制、窗口 | 屏幕上真实出现像素 |

## 设计取舍

**为什么坚持 i386 保护模式而不是 x86_64？**
32 位模式下分页是两级结构、地址空间一目了然，适合把"机制"本身讲清楚。64 位会引入四级页表、长模式切换、更复杂的段描述符，对教学目的来说是噪声。

**为什么不用现成的 multiboot 加载器？**
自研引导链意味着你必须亲手处理实模式、A20、GDT、跳转刷新 CS。这些正是本项目的核心教学价值。Bootloader 只是工具，不是要回避的难点。

**为什么要求真实硬件可达？**
模拟器掩盖时序与设备差异。当代码在 QEMU 和物理机上都跑通时，说明你依赖的是规范而不是巧合。
