# 分页与内存管理

保护模式解决了"能不能访问"，分页解决"访问到哪里"。开启分页后，CPU 发出的每个地址都要经过页表翻译，这是内核获得内存隔离能力的基础。

## 两级页表结构（i386）

```
CR3 ──► 页目录 (Page Directory, 4 KiB)
          │  每项 = PDE，指向一张页表
          ▼
        页表 (Page Table, 4 KiB)
          │  每项 = PTE，指向一个物理页
          ▼
        物理页 (4 KiB)
```

32 位线性地址被切成三段：

| 位段 | 名称 | 含义 |
|---|---|---|
| 31–22 | 页目录索引 | 选择 PDE（1024 项） |
| 21–12 | 页表索引 | 选择 PTE（1024 项） |
| 11–0 | 页内偏移 | 页内定位 |

每个 PDE/PTE 的低 12 位是标志位，关键几位：

| 位 | 名称 | 作用 |
|---|---|---|
| 0 | P | 存在位，为 0 访问即缺页 |
| 1 | R/W | 0 只读，1 可写 |
| 2 | U/S | 0 仅 ring 0 可访问，1 用户态可访问 |
| 5 | A | 访问过标记 |
| 6 | D | 脏页标记（仅 PTE 有） |

## 开启分页

```c
void paging_enable(uint32_t page_dir_phys) {
    __asm__ volatile("mov %0, %%cr3" :: "r"(page_dir_phys) : "memory");
    uint32_t cr0;
    __asm__ volatile("mov %%cr0, %0" : "=r"(cr0));
    cr0 |= 0x80000000;          // CR0.PG = 1
    __asm__ volatile("mov %0, %%cr0" :: "r"(cr0) : "memory");
}
```

::: danger 开启分页的瞬间必须身份映射
执行 `mov cr0` 那一刻，**正在执行的指令本身**也要经过地址翻译。如果内核当前所在的物理页没有出现在新页表里，下一条指令就会缺页；此时 IDT 还没准备好，直接三重故障。正确顺序是：先建立覆盖内核代码、栈、页表自身、显存的恒等映射（虚拟地址 = 物理地址），确认无误后再置位 PG。
:::

## 物理内存管理

内核需要知道哪些物理页可用。信息来源是 BIOS 提供的 `e820` 内存映射（或 `int 0x15, eax=0xE820`）。把它读进一个数组，标记出：

- **保留区**：低 1 MiB、ACPI 表、MMIO 区域 —— 不可分配
- **可用区**：`type == 1` 的区间 —— 交给分配器

分配器选型：

| 方案 | 优点 | 缺点 |
|---|---|---|
| 位图（1 bit / 4 KiB 页） | 实现简单、查找可预测 | 大内存下遍历开销 |
| 栈式空闲链表 | 分配/释放 O(1) | 碎片不合并 |
| 伙伴系统 | 合并高效、外部碎片少 | 实现复杂度高 |

教学项目从位图起步最划算：一张 bitmap 覆盖 128 MiB 只需 4 KiB。

## 内核堆

物理页分配器只给"页"，`kmalloc` 需要从页里切出小块。典型做法：

1. 从物理分配器拿一页，切成固定大小（如 16 / 32 / 64 B）的块
2. 每种尺寸一条空闲链表
3. 超过阈值（如 2 KiB）直接走页分配器

## 必须处理的边界情况

| 情况 | 后果 |
|---|---|
| 忘记身份映射页表本身 | 开启 PG 后页表不可访问，无法再修改映射 |
| 未清零 `.bss` | 分配器元数据是随机值，首次分配即崩 |
| 4 KiB 边界未对齐页目录 | CR3 低 12 位被硬件忽略，映射全部错位 |
| TLB 未刷新（改映射后） | 旧映射继续生效，写入到已释放的页 |

改完页表后刷新 TLB 的最小代价做法：

```c
__asm__ volatile("invlpg (%0)" :: "r"(vaddr) : "memory");
```

## 验证清单

- [ ] `CR0.PG` 已置位（gdb：`info registers cr0`）
- [ ] 建立映射后写入一个值，再从同一虚拟地址读出，值一致
- [ ] 访问未映射地址触发 14 号异常（缺页），且 `CR2` 里是对应虚拟地址
- [ ] 分配 1000 个页后全部释放，再次分配能成功（无泄漏）
