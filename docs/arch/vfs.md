# 文件系统与 VFS

## 为什么要先有 VFS

内核里会存在多种文件系统（自有格式、FAT、只读镜像）。如果每个调用方都直接操作某一种格式，新增一种格式就要改所有调用点。VFS 的作用是把"文件"抽象出来，让上层只依赖接口，不依赖实现。

## 抽象层

```
系统调用 (open / read / write / close / readdir)
        │
        ▼
    VFS 层：路径解析、挂载点、缓存、权限
        │
        ▼
   具体文件系统：ext2-like / FAT / ramfs
        │
        ▼
    块设备层（ATA / AHCI 驱动）
```

VFS 定义的核心操作集：

| 操作 | 语义 |
|---|---|
| `lookup` | 在目录中按名字找 inode |
| `create` / `unlink` | 创建 / 删除目录项 |
| `read` / `write` | 按偏移读写 |
| `readdir` | 遍历目录项 |
| `stat` | 返回元数据 |

## 路径解析

`/a/b/c` 的解析过程：

1. 从当前目录（或根）开始
2. 按 `/` 切分，逐段调用 `lookup`
3. 最后一段得到目标 inode
4. 处理特殊情况：`.`、`..`、连续斜杠、符号链接、相对路径、路径长度上限

::: warning 路径解析是最容易出现安全漏洞的地方
`..` 在根目录时不能逃逸到根之上；空段要跳过；超长路径要有上限。这些边界在用户态程序里最好测（`open("../../../../etc/passwd")`），内核里一旦漏掉就是越权访问。
:::

## 自有文件系统的最小布局

一个教学可用的设计：

| 区域 | 内容 |
|---|---|
| 引导块 | 保留，可由引导代码使用 |
| 超级块 | 魔数、块大小、inode 总数、空闲位图位置 |
| inode 位图 | 每个 inode 一位 |
| 数据块位图 | 每个块一位 |
| inode 表 | 固定大小记录：类型、大小、权限、直接块指针、间接块指针 |
| 数据区 | 实际内容 |

inode 的块指针一般分两级：12 个直接块 + 1 个一级间接块，足以覆盖大文件同时保持实现简单。

## 与块设备衔接

文件系统只依赖两个原语：

```c
int blk_read(uint32_t lba, uint32_t count, void *buf);
int blk_write(uint32_t lba, uint32_t count, const void *buf);
```

把这两个函数固定在块设备层，之后换 ATA PIO 还是 AHCI，文件系统代码一行都不用改。

## 挂载

挂载点让一棵目录树可以接入另一棵树：

1. 在父文件系统里分配一个空目录作为挂载点
2. 记录 `(挂载点 inode) → (子文件系统根 inode)` 的映射
3. 路径解析走到挂载点时，跨界进入子文件系统的根
