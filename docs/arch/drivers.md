# 驱动模型（PCI / ATA / AHCI / USB）

## 统一驱动接口

设备驱动在本项目里遵循"探测—初始化—服务"三段式：

| 阶段 | 职责 | 失败处理 |
|---|---|---|
| probe | 判断该设备是否由本驱动接管 | 返回未匹配，交给下一个驱动 |
| init | 分配资源、复位设备、注册中断 | 回滚已申请资源并返回错误 |
| serve | 响应读写请求 | 返回错误码，不阻塞调用方 |

驱动注册到总线对象上，而不是硬编码调用。这样加一种新设备不需要改内核核心逻辑。

## PCI 枚举

PCI 配置空间通过 I/O 端口 `0xCF8`（地址）与 `0xCFC`（数据）访问：

```c
uint32_t pci_read32(uint8_t bus, uint8_t slot, uint8_t func, uint8_t off) {
    uint32_t addr = (1u << 31)
                  | ((uint32_t)bus  << 16)
                  | ((uint32_t)slot << 11)
                  | ((uint32_t)func << 8)
                  | (off & 0xFC);
    outl(0xCF8, addr);
    return inl(0xCFC);
}
```

枚举要点：

- `vendor_id == 0xFFFF` 表示该位置无设备
- 先读 header type（偏移 `0x0E`）判断是单功能还是多功能设备
- 多功能设备需遍历 `func 0..7`
- BAR（偏移 `0x10`–`0x24`）最低位为 1 表示 I/O 空间，为 0 表示内存映射

## ATA / AHCI

| 接口 | 访问方式 | 特点 |
|---|---|---|
| ATA PIO | I/O 端口 `0x1F0` 起 | 实现最简单，CPU 全程阻塞，适合起步 |
| AHCI | MMIO + 命令队列 | 需要 DMA、命令列表、FIS 结构，性能与真实硬件贴合 |

从 PIO 起步的关键步骤：

1. 读状态端口 `0x1F7`，等待 BSY 清、DRDY 置
2. 选主/从盘（`0x1F6`）
3. 设置 LBA 与扇区数，发 `0x20`（读）或 `0x30`（写）
4. 轮询等待 DRQ 置位
5. 从 `0x1F0` 连续读 256 次 `uint16_t` = 512 字节

::: warning 轮询必须有超时
磁盘不存在或未就绪时，状态位永远不会置位。没有超时的 `while` 轮询会让内核永久挂死，且没有任何日志——这是最耗时的调试场景之一。每个等待位都要配一个最大循环次数。
:::

## USB

本项目涉及的 XHCI 控制器（USB 3.x）使用**环形命令队列 + 事件环**模型：

1. 找到 XHCI 的 MMIO BAR
2. 复位控制器，设置 `CONFIG.MaxSlots` / `MaxPorts`
3. 分配并注册 DCBAA（设备上下文基址数组）
4. 建立命令环与事件环，写 `CRCR` / `ERSTBA`
5. 轮询事件环，处理 Port Status Change 事件
6. 对每个端口执行复位、取设备描述符、设置地址、配置端点

关键坑点：

| 坑 | 后果 |
|---|---|
| 环形缓冲区物理地址未 64 字节对齐 | 控制器拒绝运行 |
| 未处理 Event Ring 的 EHB 位 | 中断风暴或事件丢失 |
| 忽略 TRB 的 Cycle bit | 控制器认为该 TRB 无效，命令永不完结 |
