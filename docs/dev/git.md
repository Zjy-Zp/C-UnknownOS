# 提交与分支约定

## 分支模型

| 分支 | 用途 |
|---|---|
| `main` | 始终可启动、可构建 |
| `feat/<子系统>-<简述>` | 单个特性的开发 |
| `fix/<问题简述>` | 缺陷修复 |
| `tag vX.Y.Z` | 每个里程碑（如首次进保护模式、首次能读盘） |

硬性规则：**`main` 上任何提交都必须能在 QEMU 无头模式启动到自检通过**。不可启动的中间状态留在特性分支。

## 提交信息

```
<子系统>: <一句话说明>

<为什么这么改，遇到了什么现象，怎么验证的>
```

示例：

```
paging: 修复开启 PG 后立即三重故障

原因：内核代码页未建立恒等映射，mov cr0 后取指即缺页。
处理：在置位 PG 前先填充覆盖 0~16MiB 的恒等映射表。
验证：QEMU 无头启动，串口输出 "paging enabled"，-d int 日志无异常。
```

## 里程碑 tag

建议在能真实观测到成效的节点打标签：

| 里程碑 | 验收标准 |
|---|---|
| `boot-protected` | 串口打印进入保护模式 |
| `paging-on` | 分页开启且可读写映射页 |
| `irq-ok` | 键盘中断可响应 |
| `disk-rw` | 可读写磁盘扇区 |
| `fs-mount` | 自有文件系统可挂载并读写文件 |
| `net-ping` | ICMP 回显成功 |
| `gui-on` | 帧缓冲绘出图形 |

## 文档同步

改动涉及以下内容时，必须同步更新本站对应页面：

- 构建命令或编译标志变化 → [工具链](/guide/toolchain)
- 启动参数或验证方式变化 → [QEMU 无头验证](/guide/qemu-verify)
- 子系统接口或验证目标变化 → 对应架构页面

文档和代码同一个提交里一起改，避免文档腐烂。
