# 编码规范

## 语言与风格

| 项 | 约定 |
|---|---|
| 标准 | C11（`-std=gnu11`），不允许使用 C++ 特性 |
| 缩进 | 4 空格，不使用 Tab |
| 命名 | 函数 `snake_case`，类型 `xxx_t`，宏全大写 |
| 头文件保护 | `#ifndef CUNOS_<DIR>_<FILE>_H` |
| 头文件包含 | 公共头文件用 `#include <cunos/xxx.h>`，私有用 `"xxx.h"` |

## 内核代码禁忌

这些在用户态理所当然的写法，在内核里全部不可用或危险：

| 禁止 | 原因 | 正确做法 |
|---|---|---|
| `malloc` / `free` | 无 libc | 用 `kmalloc` / `kfree` |
| `printf` | 无 libc、无缓冲、可能重入 | 用 `kprintf`，且不依赖浮点 |
| 浮点运算 | FPU 上下文未保存，早期阶段会异常 | 全部用整数或定点 |
| 长时关中断 | 影响时钟精度与响应 | 临界区尽量短，用 `pushf/cli` 成对包裹 |
| 递归 | 内核栈通常只有 8–16 KiB | 改迭代 |
| 大栈上局部数组 | 同上，易踩栈 | 静态分配或走堆 |
| 阻塞等待无超时 | 设备异常时内核挂死 | 所有轮询配超时上限 |

## 并发

中断上下文与主流程上下文会竞争同一数据结构。规则：

1. 与中断处理函数共享的数据，访问前必须关中断
2. 关中断范围只覆盖真正共享的那几行
3. 中断处理函数里不做耗时操作（磁盘 IO、长时间循环）
4. 中断处理函数里不调用可能睡眠的函数

```c
static inline uint32_t irq_save(void) {
    uint32_t flags;
    __asm__ volatile("pushf; pop %0; cli" : "=r"(flags) :: "memory");
    return flags;
}

static inline void irq_restore(uint32_t flags) {
    __asm__ volatile("push %0; popf" :: "r"(flags) : "memory", "cc");
}
```

## 错误处理

- 内核初始化失败一律显式输出原因，不要静默返回
- 资源申请失败必须回滚已申请的部分
- 用户态传入的指针必须先验证落在用户地址空间内，再解引用

## 注释

注释解释"为什么"，不解释"是什么"。寄存器操作、硬件时序、绕过某个硬件缺陷的变通做法，必须写清原因与参考手册章节。

## 提交前自查

- [ ] 在 QEMU 中能启动到改动点之后
- [ ] 新增的硬件操作有超时保护
- [ ] 没有引入浮点指令（`objdump` 检查）
