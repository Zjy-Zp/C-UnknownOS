# 第 19 章 性能预期与优化

## 19.1 先测，再优化：一次进入/退出的成本

所有优化都必须建立在一个实测数字上：**一次 `VMRUN` + 一次 `#VMEXIT` + 分发处理，总共多少 CPU 周期。**

```c
/* 在 vm_run 循环里插入（debug 构建） */
u64 t0 = rdtsc();
vcpu_enter_guest(vc);
u64 t1 = rdtsc();

g_last_vmexit_cost = t1 - t0;
if (g_last_vmexit_cost > g_max_vmexit_cost) g_max_vmexit_cost = g_last_vmexit_cost;
/* 滑动平均，避免单次抖动误导 */
g_avg_vmexit_cost = (g_avg_vmexit_cost * 15 + (t1 - t0)) / 16;
```

经验量级（**必须在目标机器上实测，此处仅用于规划**）：

| 项 | 量级 | 说明 |
|---|---|---|
| `VMRUN` 进入 | 数百至一千余周期 | 包含保存/加载 guest 状态 |
| `#VMEXIT` 退出 | 数百至一千余周期 | 与 VMRUN 同量级 |
| 一次完整往返 + 分发 | 约 1–3 千周期 | 我们自己的 C 代码（分发 + 设备处理）占比不小 |

在 3GHz 上，1 万次退出/秒 ≈ 3–10% 的 CPU。**这个数字决定一切**：如果 guest 每秒触发 100 万次退出，宿主的 100% CPU 都在做"进出"。

## 19.2 各阶段的退出预算

| 阶段 | 场景 | 每秒退出数（估） | 是否可接受 |
|---|---|---|---|
| 1 | hello guest | 几十次/秒 | 完全可接受 |
| 2 | 空闲 guest（等 PIT） | 18–100 次/秒（PIT tick） | 可接受 |
| 3 | Debian 启动（内核初始化） | 数万至数十万次/秒 | 勉强，启动会慢 5–20 倍 |
| 4 | 交互使用（shell、编译） | 数千次/秒 | 可接受 |
| 4+ | 大规模磁盘 IO（`apt install`） | 百万级（若 ATA PIO 逐字节） | **不可接受**，必须 virtio |

## 19.3 减少退出的五个手段

**手段一：拦截位最小化。** 只拦真正需要的。阶段 3 的最小集：

```c
/* 只拦截：HLT、IOIO、MSR、CPUID、SHUTDOWN、VMRUN、VMMCALL、PAUSE（可选） */
u64 icpt = 0;
icpt |= (1ull << 24);            /* HLT */
icpt |= (1ull << 27);            /* IOIO */
icpt |= (1ull << 28);            /* MSR */
icpt |= (1ull << 26);            /* CPUID */
icpt |= (1ull << 31);            /* SHUTDOWN */
icpt |= (1ull << 0);             /* VMRUN（防 guest 自己虚拟化） */
icpt |= (1ull << 2);             /* VMMCALL */
```

**【需核对】这些 bit 编号必须按 APM 的 VMCB intercept 表核对。** 本文的编号来自常见的 bit 位置（HLT=24、CPUID=26、IOIO=27、MSR=28、SHUTDOWN=31），但**绝不能凭记忆上线**——拦错一位的表现可能是"guest 直接跑了 `VMRUN`"，或者"IOIO 不退出，guest 直接操作了宿主的真实端口"（灾难级）。

**手段二：字符串 IO 批量处理（收益最大）。** ATA PIO 读一个 512 字节扇区，guest 用 `rep insw`，若逐次退出就是 256 次；若识别为字符串指令**一次退出搬完**，就是 1 次。

```c
/* 在 ex_ioio 里识别字符串指令 */
static int io_is_string(vcpu_t *vc, u64 info1)
{
    /* 【需核对】exit_info_1 中"是否为字符串指令"的标志位位置 */
    return (int)((info1 >> 4) & 1);     /* 示意位，必须核对 */
}

static int ex_ioio_string(vcpu_t *vc, u16 port, u32 width, int is_in)
{
    u32 count = vmcb_rd32(vc->vmcb, VMCB_OFF_RCX);
    u32 gpa   = vmcb_rd32(vc->vmcb, is_in ? VMCB_OFF_RDI : VMCB_OFF_RSI);
    u32 step  = width;
    if (!gpa_range_ok(vc->vm, gpa, (u64)count * step)) { inject_gp(vc); return 0; }

    vdev_t *d = vdev_find_io(vc->vm, port);
    if (!d) { inject_gp(vc); return 0; }

    u8 *p = (u8 *)ram_va(gpa);
    if (is_in) {
        if (d->ops->io_read_block) {
            d->ops->io_read_block(d, port, count, width, p);     /* 一次搬完 */
        } else {
            for (u32 i = 0; i < count; i++) {
                u32 v = 0;
                d->ops->io_read(d, port, width, &v);
                memcpy(p + i * step, &v, step);
            }
        }
    } else {
        for (u32 i = 0; i < count; i++) {
            u32 v = 0;
            memcpy(&v, p + i * step, step);
            d->ops->io_write(d, port, width, v);
        }
    }
    /* 更新 RCX=0，RDI/RSI 前推 count*step */
    vmcb_wr32(vc->vmcb, VMCB_OFF_RCX, 0);
    vmcb_wr32(vc->vmcb, is_in ? VMCB_OFF_RDI : VMCB_OFF_RSI, gpa + count * step);
    vmcb_wr64(vc->vmcb, VMCB_OFF_RIP, vmcb_rd64(vc->vmcb, VMCB_OFF_RIP) + io_insn_len(vc));
    return 0;
}
```

**这一个优化能把 ATA PIO 的退出数降低 256 倍**，是"阶段 3 能不能忍"的分水岭。注意 `DF`（方向标志）为 1 时方向相反，必须检查 `RFLAGS.DF`。

**手段三：MSR 白名单直通。** 内核态频繁读写 `FS_BASE`/`GS_BASE`/`STAR`（上下文切换）会让 MSR 退出变成热点。让这些在 MSRPM 里"放行"（不拦截）能显著降低退出数——**前提是我们确认它们不需要虚拟化**（单 vCPU 下 FS/GS base 可以直通，因为只有一个 guest 在用）。

**手段四：HLT 退出合并。** 空闲 guest 每个 tick 都 `HLT` 退出一次是正常的（18 次/秒），不必优化。但**不要**把 HLT 拦截关掉——关了 guest 会真的 `hlt` 硬件，宿主跟着睡死。

**手段五：NPT 直通映射（消除 NPF 退出）。** 帧缓冲用"首次 NPF 后整页直通"（13.7）；大块 RAM 用 2MB 大页（避免 4KB 页在 TLB 里被冲掉）。

## 19.4 ASID 与 TLB

`ASID`（Address Space ID）让不同 guest 的 TLB 项共存，避免每次 `VMRUN` 都要 `TLB_CTL` 全刷。我们的用法：

```c
/* 每个 vm 分配一个 ASID（1..255，0 保留给宿主） */
vm->asid = vmm_alloc_asid();

/* VMRUN 前不需要刷 TLB —— 只要 ASID 不变 */
/* 只有 NPT 映射发生变化且影响已缓存项时才刷 */
static void npt_flush(vcpu_t *vc, int all)
{
    if (all) {
        vmcb_wr32(vc->vmcb, VMCB_OFF_TLB_CTL, 1);        /* 【需核对】flush 的位定义 */
    } else {
        __asm__ volatile("invlpga %%eax, %%ecx" :: "a"(0), "c"(vc->vm->asid));
    }
}
```

三点：

1. **`INVLPGA` 的第二个操作数在 ECX**（不是 EDX），这是 32 位下必须写对的细节；64 位才是 `RAX`/`ECX` 组合。
2. **ASID 0 是特殊的**（"不支持 ASID"的语义），分配时从 1 开始。
3. **NPT 修改后必须刷**，否则 guest 会读到旧的翻译——这类 bug 的症状是"偶发的、与内存分配时机相关的崩溃"，极难定位。**规则：任何 `npt_map_page` 之后立即 `npt_flush(1)`**，宁可慢也不要错。

## 19.5 抢占：cunos 协作式调度的硬约束

cunos 的调度是**协作式**的（只在 `int 0x80` 里切换）。这意味着：**一旦 `vm_run()` 开始循环，宿主内核就再也不会被调度**，直到 guest 主动退出循环。

这对 VMM 是致命的：

- guest 死循环（比如 Debian 内核在某个轮询里等一个永不来的位）→ 宿主整个系统失去响应；
- 用户无法按 `Ctrl-C` 回到 shell；
- 无法在 guest 运行时执行宿主命令（"vm stat" 得等 guest 退出）。

**缓解方案（按可行性排序）：**

| 方案 | 做法 | 代价 |
|---|---|---|
| **退出预算** | `vm_run` 循环里计数，每 N 次退出（如 10000）就返回 `VCPU_EXIT_TIMESLICE`，由调用者决定是否再进入 | 需要"可恢复的 vm_run"，改造成本低，**推荐** |
| **PIT 驱动的时间片** | 在 `pit_tick` 里检查已运行 tick 数，超时就把 `vc->need_resched = 1`，主循环检查后返回 | 与上一条配合 |
| **抢占式改造** | 把 PIT 中断接进宿主 IDT，在中断里做上下文切换 | 需要大改 `proc.c` 与 `idt.c`，超出本阶段范围 |
| **看门狗** | 宿主用另一个 CPU 核（SMP）监视并强杀 | cunos 尚不支持 SMP |

推荐实现：

```c
#define EXIT_BUDGET 50000       /* 每 5 万次退出让出一次 */

int vm_run(vm_t *vm)
{
    vcpu_t *vc = vm->vcpus;
    u32 budget = 0;

    for (;;) {
        vcpu_enter_guest(vc);
        ...
        if (++budget >= EXIT_BUDGET || vc->need_resched) {
            /* 保存当前状态，返回"时间片用完" */
            vm->state = VM_STATE_READY;      /* 不是 STOPPED，可以再进 */
            return VCPU_EXIT_TIMESLICE;
        }
    }
}
```

调用者（shell 命令）则：

```c
while (vm_run(vm) == VCPU_EXIT_TIMESLICE) {
    if (kbd_ctrl_c_pressed()) break;        /* 可以响应 Ctrl-C */
    /* 也可以在这里做宿主侧的事：刷新屏幕、检查定时任务 */
}
```

**这个设计让"guest 死循环"从"宿主失去响应"降级为"用户能按 Ctrl-C"。价值极高，优先级应排在性能优化之前。**

## 19.6 AVIC / VAPIC：为什么阶段 5 也不做

AVIC（Advanced Virtual Interrupt Controller）允许**硬件直接向 vCPU 注入中断，无需 `#VMEXIT`**，理论上能省掉大量中断退出。但它的前提是：

1. 客户机使用 x2APIC 模式，且我们提供 AVIC 的 APIC backing page（`VMCB.AVIC_APIC_BAR`）；
2. 需要 **IOMMU** 参与（中断重映射表），否则设备中断无法直接投递；
3. 需要 AVIC 逻辑 APIC ID 表（`AVIC_LOGICAL_TABLE`）。

cunos 目前没有 IOMMU 支持、没有 APIC 驱动、没有 x2APIC。**引入 AVIC 等于同时实现 IOMMU 中断重映射 + x2APIC + AVIC 表结构**，工作量远超项目本体。

结论：**不做 AVIC，用 8259A + `V_IRQ` 注入（13.2）就够**。单 vCPU 下的中断注入开销本来就不高（每个 tick 一次），优化的性价比远低于"减少 IO 退出"。

## 19.7 串口才是阶段 3 的真瓶颈

这是一个必须写进文档的反直觉结论。115200 bps 的串口，每字节约 87μs。Debian 启动时的内核日志量（含 `earlyprintk`）经常在 **1–5MB** 量级：

- 1MB 日志 ≈ 87 秒纯串口传输时间；
- 而 UART 的 `serial_putc` 是**轮询等待 THRE**（因为没有中断驱动），意味着宿主在这段时间里什么都做不了。

**优化（按收益排序）：**

1. **降日志量**：内核参数里去掉 `debug`、`ignore_loglevel`；只保留 `loglevel=4`（只打 warning 以上）。
2. **提高波特率**：`console=ttyS0,921600` + 宿主串口设备支持 921600（很多 USB-TTL 支持）。8 倍提速。
3. **环形缓冲 + 延迟输出**：`vdev_uart` 把字符写进 64KB 环形缓冲，由"宿主侧的 flush 任务"（每次 `vm_run` 时间片返回时）批量吐到串口。**这样 guest 的输出不再阻塞 guest 的执行**——guest 打印 1MB 日志照样 1 秒跑完，只是日志慢慢出现在屏幕上。
4. **只在需要时开 trace 级日志**（`g_vmm_log_level` 默认 2）。

第 3 条是真正的解法，代码约 40 行：

```c
typedef struct { u8 buf[65536]; u32 head, tail; } ring_t;

static void uart_out_byte(vdev_t *d, u8 c)
{
    ring_t *r = &((uart_t *)d->priv)->tx_ring;
    u32 nxt = (r->head + 1) & 0xFFFF;
    if (nxt == r->tail) {            /* 满：丢最老的，绝不阻塞 guest */
        r->tail = (r->tail + 1) & 0xFFFF;
    }
    r->buf[r->head] = c;
    r->head = nxt;
}

void uart_flush_to_host(vdev_t *d)   /* 在 vm_run 时间片返回时调用 */
{
    ring_t *r = &((uart_t *)d->priv)->tx_ring;
    u32 n = 0;
    while (r->tail != r->head && n < 4096) {       /* 每次最多吐 4KB */
        serial_putc(r->buf[r->tail]);
        r->tail = (r->tail + 1) & 0xFFFF;
        n++;
    }
}
```

## 19.8 性能优化的优先级排序

1. **退出预算 + 可恢复 `vm_run`**（可用性，不是性能）
2. **字符串 IO 批量**（数量级收益）
3. **串口环形缓冲**（把"等待"变成"异步"）
4. **virtio-blk**（磁盘 IO 数量级收益）
5. **NPT 2MB 大页**（TLB 命中率）
6. **MSR 白名单直通**（上下文切换热点）
7. ASID 调优、拦截位精调（边际收益）
8. AVIC（不做）
