# 第 6 章 NPT 嵌套分页

## 6.1 为什么必须用 NPT

guest 有自己的页表（它以为自己在改 CR3）。硬件要完成"guest 虚拟地址 → 宿主物理地址"的翻译，必须先按 **guest 页表**（其表项里是 GPA）走一遍，再对每一级表项地址做 **GPA → HPA** 的第二次翻译。这就是两级翻译（nested paging）。

若硬件没有 NPT（`CPUID.8000000A.EDX[0] = 0`），唯一出路是**影子页表**：宿主为 guest 的每一份页表维护一份"已翻译成 HPA"的副本，并在 guest 每次改页表时同步。这条路线的复杂度是 NPT 的 3–5 倍，且要拦截 guest 的每一次页表写——本文直接放弃（`svm_probe()` 里硬性拒绝）。

## 6.2 NPT 表项格式与层级

**NPT 表项是 8 字节（64 位）格式**，与 PAE/长模式页表项同构，而不是 cunos 现有 paging 用的 4 字节格式。这是全章第一个必须记住的事实：`npt.c` 里所有表都是 `u64 t[512]`，一页正好 512 项。**【需核对：APM Vol.2 Appendix B 中 NPT 表项位定义，特别是 NX 位是否要求 EFER.NXE=1】**

| 位 | 名称 | 说明 |
|---|---|---|
| 0 | P | 存在 |
| 1 | RW | 可写 |
| 2 | US | 用户可访问 |
| 3 | PWT | 写通 |
| 4 | PCD | 禁缓存（MMIO 必置） |
| 5 | A | 已访问（硬件置） |
| 6 | D | 已脏（硬件置） |
| 7 | PS | 大页（在 PDP/PD 层有效） |
| `11:8` | — | 忽略/可用 |
| `51:12` | 物理地址 | HPA 页帧号 |
| 63 | NX | 不可执行 |

层级：NPT 与长模式页表**同构**，从 `nCR3` 指向的根表开始是 4 级（PML4 → PDP → PD → PT），每级 512 项。对 32 位非 PAE 的 guest，其自身页表只有 2 级（PDE → PTE），但**宿主侧的 NPT 仍然是 4 级结构**。

> **这一条必须先用 5 分钟实验确认，再写代码。**实验方法：手工构造成下面这种"只有第一项有效的 4 级表"，把 guest 的第一条指令所在的 GPA 映射到一段真实内存，然后 VMRUN：
>
> - 如果 guest 能取到第一条指令并因 `hlt`（或其他已拦截事件）退出 → **4 级假设成立**，按本文写；
> - 如果 VMRUN 立即 `#GP`/`#UD` 或退出码是 `NPF` 且 `exit_info_2` 为 0 → 说明层级假设错了（可能顶层被折叠），需按实测层级重建。
>
> 这个实验的代码在第 11.3 节，属于阶段 1 的第一步，**不要跳过**。因为它决定了 `npt.c` 里所有索引移位的正确性，写错的话后面每一个 guest 访问都会 NPF。

## 6.3 NPT 表在 cunos 里的存放位置

NPT 表项里必须填 **HPA**。因此：

1. NPT 表本身从**控制池**（`VMM_CTL_PA_BASE = 0x03000000` 起，16MB）分配，物理连续、4KB 对齐；
2. 宿主读写 NPT 表要经过**控制窗口** `VMM_CTL_VA_BASE = 0xDFC00000`（映射方式见 8.5），拿到的是可直接解引用的虚拟地址；
3. 绝不把 NPT 表放在 `pmm` 池里——理由见 8.5：`pmm` 池所在的 4MB 块会被用户进程的页表拆分，那里的"物理地址 == 虚拟地址"性质不再稳定。

## 6.4 NPF 退出与 EXITINFO1 位域

guest 访问一个"在 guest 页表里有效、但在 NPT 里无效/无权限"的地址时，产生退出码 `0x400`（NPF）。此时：

- `exit_info_1` = NPF 错误码；
- `exit_info_2` = 出错的 **GPA**（4KB 对齐）。

`exit_info_1` 位域（**需核对**，但下列语义是通行理解）：

| 位 | 名称 | 为 1 的含义 |
|---|---|---|
| 0 | P | 1 = 违反了页保护（页本身存在）；0 = 页不存在 |
| 1 | W/R | 1 = 写访问；0 = 读访问 |
| 2 | U/S | 1 = guest 在用户态发起的访问 |
| 3 | RSVD | 1 = 保留位被置（NPT 表构造错误，**必须 panic**） |
| 4 | ID | 1 = 取指（instruction fetch） |
| 5 | PK | 保护键相关【需核对】 |

处理算法（`npt_handle_npf()`）：

```c
int npt_handle_npf(vcpu_t *vc)
{
    u32 err  = (u32)vc->vmcb->exit_info_1;
    u32 gpa  = (u32)vc->vmcb->exit_info_2 & ~0xFFFu;

    if (err & (1u << 3)) {           /* RSVD：表项构造错，绝不可恢复 */
        serial_puts("NPF: reserved bit set, gpa=0x");
        serial_hex(gpa);
        serial_puts(" err=0x"); serial_hex(err); serial_putc('\n');
        return -1;
    }

    /* 情况 1：这个 GPA 属于 RAM 洞，按需分配（demand paging） */
    if (gpa >= VMM_RAM_GPA_LIMIT && gpa < VMM_MMIO_HOLE_BASE) {
        /* 未映射，但仍在 RAM 范围内 → 分配零页并建立映射 */
        return npt_map_ram_4k(vc->npt, gpa);
    }

    /* 情况 2：MMIO 区域（VGA/PCI BAR/APIC） */
    if (vmm_is_mmio(gpa)) {
        return vdev_mmio_fault(vc, gpa, err);
    }

    /* 情况 3：COW 页的写触发 —— 拷贝一份再重映射 */
    if ((err & 1) && (err & 2)) {
        return npt_cow_break(vc->npt, gpa);
    }

    /* 情况 4：真正的非法访问，按 guest 页表语义注入 #PF */
    return vcpu_inject_pf(vc, gpa, err);
}
```

四个分支的判据必须严格按顺序，因为一个 GPA 可能同时满足多个条件的表面特征（例如 MMIO 区也可能被写）。**先判 RSVD，再判地址空间归属，最后才注入异常**——顺序错了会出现"guest 里一个正常的内存写导致整机 panic"这种极难排查的问题。

注入 `#PF` 的写法（`eventinj` 字段，**【需核对偏移与位布局】**）：

```c
/* eventinj 32 位布局（通行理解）：
 *   bit 31    : 有效（V）
 *   bit 11    : 错误码有效（E）
 *   bit 10:8  : 类型（0=中断, 3=硬件异常, 4=软件中断, 5=特权软件异常）
 *   bit 7:0   : 向量号
 * 错误码写在 eventinj 的高 32 位。
 */
void vcpu_inject_pf(vcpu_t *vc, u32 gpa, u32 npf_err)
{
    u32 ecode = 0;
    if (npf_err & 1) ecode |= 0x1;     /* P */
    if (npf_err & 2) ecode |= 0x2;     /* W */
    if (npf_err & 4) ecode |= 0x4;     /* U */
    if (npf_err & 16) ecode |= 0x10;   /* I/D */

    vc->vmcb->eventinj = ((u64)ecode << 32) | (1u << 31) | (1u << 11) | (3u << 8) | 14u;
    /* guest 的 CR2 也要填（硬件在 guest 下次读取时才看到） */
    vc->vmcb->cr2 = gpa;
}
```

## 6.5 大页

两级翻译都支持大页，收益极大（映射 128MB RAM 用 4KB 页需要 32768 个 PTE + 32 个 PT + 32 个 PD 项；用 2MB 页只需 64 个 PD 项）。

| 层级 | PS 位 | 页大小 | cunos 用法 |
|---|---|---|---|
| PD（第 3 级） | 1 | 2MB | **RAM 主体用 2MB 大页** |
| PDP（第 2 级） | 1 | 1GB | 不使用（需要宿主 PA 支持 1GB 对齐，且与 RAM 布局冲突） |

大页的两个坑：

1. **对齐全靠地址对齐**。2MB 大页要求 GPA 与 HPA 都 2MB 对齐。我们的 RAM 池物理起点 `0x04000000`（64MB）本身 2MB 对齐，GPA 0 也对齐，因此 `npt_map_2m(gpa, gpa + VMM_RAM_PA_BASE)` 可整段铺开。
2. **大页内部无法做细粒度保护**（比如"只让 guest 只读某 4KB"）。因此 RAM 全部先用 2MB 铺开，等 guest 需要 COW 或 MMIO 精细映射时，再**拆大页**：

```c
/* 把 [gpa, gpa+2MB) 的 2MB 大页拆成 512 个 4KB 页项 */
int npt_split_2m(npt_t *n, u32 gpa)
{
    u64 *pd = npt_walk_to_pd(n, gpa);
    u64 *e  = &pd[(gpa >> 21) & 0x1FF];
    if (!(*e & 1) || !(*e & (1ull << 7))) return -1;   /* 不是大页，无需拆 */
    u32 pa = npt_pa(n, ctl_alloc_page());
    if (!pa) return -1;
    u64 *pt = (u64 *)ctl_va(pa);
    u64 base = *e & 0x000FFFFFFFE00000ull;
    for (u32 i = 0; i < 512; i++)
        pt[i] = (base + (u64)i * 0x1000ull) | (*e & 0xFFFull);
    *e = (u64)pa | (*e & 0xFFFull) & ~(1ull << 7);
    npt_flush_all(n);      /* 表结构变了，必须刷 */
    return 0;
}
```

## 6.6 TLB 与 INVLPGA

guest TLB 里缓存的是**翻译的最终结果**（GVA → HPA），它同时依赖 guest 页表和 NPT。因此：

- **guest 改了自己的页表并执行 `invlpg`**：宿主需代为执行 `invlpg`（或让硬件自己处理——`invlpg` 在 guest 里是本地操作，不需要宿主参与；只有当它被拦截时宿主才需要办事）；
- **宿主改了 NPT 表**：必须让 guest TLB 失效，手段是 `INVLPGA`（`EAX` = 虚拟地址，`ECX` = ASID）。若刷全部，用 `EAX=0, ECX=0`。

cunos 的策略：

```c
void npt_flush_all(npt_t *n)
{
    svm_invlpga(0, 0);      /* ASID 0 = 刷全部 */
}
```

代价：刷全部 TLB 之后 guest 的每次内存访问都要重新走两级翻译（每次最多 4+2 次内存访问）。因此**不要在每个 NPF 处理完后都刷**——只在表**结构**（层级、大页/小页）变化时刷；只改 PTE 权限时，也可以只刷对应页（`invlpga(gva, asid)`），但需要 GVA，而 NPF 只给 GPA。折中：阶段 2 一律全刷，阶段 4 再优化（第 19 章）。

## 6.7 NPT 的建立与 cunos 内存布局的衔接

```c
/* 初始 NPT：RAM 全用 2MB 大页铺开；MMIO 洞留给 vdev 按需映射 */
int npt_build(npt_t *n, u32 ram_size)
{
    u32 root = ctl_alloc_page();
    if (!root) return -1;
    n->pml4 = (u64 *)ctl_va(root);
    n->ncr3_pa = root;
    memset(n->pml4, 0, 4096);

    for (u32 off = 0; off < ram_size; off += 0x200000u) {
        if (npt_map_2m(n, off, VMM_RAM_PA_BASE + off, 0x007) < 0)  /* P|RW|US */
            return -1;
    }
    serial_puts("NPT: ram="); serial_dec(ram_size >> 20);
    serial_puts("MB ncr3=0x"); serial_hex(root); serial_putc('\n');
    return 0;
}
```

`0x007` 表示 `P|RW|US`：guest 的内核态与用户态都能访问（guest 自己的页表里 U/S 位才是隔离手段；NPT 这一层对 guest 内核/用户不做区分，除非要防 guest 内核越权访问自己用户页——那是 guest 内部的事）。

## 6.8 宿主如何访问 guest 内存

这是"必须写成硬规则"的一条：**宿主代码永远不能把 GPA 当作地址解引用**。所有访存走一个函数：

```c
static inline void *ram_va(u32 gpa)      /* guest RAM 的虚拟窗口 */
{
    if (gpa >= VMM_RAM_MAX) return 0;
    return (void *)(VMM_RAM_VA_BASE + gpa);
}
```

`VMM_RAM_VA_BASE = 0xE0000000`，窗口大小 128MB，通过 `paging_map_page()` 逐页映射到 `VMM_RAM_PA_BASE + gpa`（见 8.5 的映射代码）。窗口的 PTE 权限必须是 `0x003`（内核可读写、非用户页），否则 ring 3 的 cunos 用户程序可以直接读写整个 guest 内存。

有了 `ram_va()`，宿主读写 guest 内存就是普通指针操作，并且**不经过 NPT**——这是正确的：NPT 只约束 guest 视角的翻译，宿主对物理内存的直接访问不受 NPT 影响。

## 6.9 一个容易忽略的细节：AMO 与跨页访问

guest 的一条 `rep movsb` 或一次跨 4KB 边界的访问，可能在两级翻译下跨越两套页表项。语义上这是允许的（硬件逐页翻译），但 NPF 可能**在中间某页触发**，此时：

- 已经拷贝的部分**已经生效**（不是事务性的）；
- `RIP` 仍指向那条 `rep movsb`，`RCX/RSI/RDI` 已被硬件递减/递增；
- 因此宿主处理完 NPF、`VMRUN` 回去后，指令会**从断点继续**执行——这正是正确行为，**不要**试图把 RIP 前推或重放整条指令。

这条结论对立项"能不能跑 `dd`"很关键：`dd` 大量使用 `rep movsb`，只要按上述语义处理，跨页拷贝是天然正确的。
