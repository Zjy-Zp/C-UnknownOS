# 第 22 章 附录

## 22.1 附录 A：真机前置检查清单

在写第一行 VMM 代码之前，先把下面这张表填完。任何一项不满足，后续全部工作都会白费。

| # | 检查项 | 操作方法 | 期望结果 |
|---|---|---|---|
| A1 | CPU 是 AMD（不是 Intel） | 看 CPU 型号；或宿主跑 `CPUID 0x00000000` 读 vendor 字符串 | `AuthenticAMD` |
| A2 | CPU 支持 SVM | `CPUID 0x80000001.ECX[2]` | 为 1 |
| A3 | CPU 支持 NPT | `CPUID 0x8000000A.EDX[0]` | 为 1 |
| A4 | CPU 支持 64 位 | `CPUID 0x80000001.EDX[29]` | 为 1（**NPT 表项是 8 字节，几乎所有 NPT 实现都假定宿主在长模式下工作过；即使我们的内核是 32 位，也需要确认硬件具备该能力**，详见 6.x 的说明） |
| A5 | BIOS 里 SVM 已启用 | 进 BIOS 找 "SVM Mode" / "AMD-V" / "Virtualization"，设为 Enabled | 开启 |
| A6 | `VM_CR.SVMDIS = 0` | 读 `MSR 0xC0010114`，看 bit4 | 为 0（为 1 说明被锁，通常要开 BIOS 选项或断电重启） |
| A7 | 内存 ≥ 1GB | 看开机自检 | 建议 2GB（宿主 + 128MB guest + 余量） |
| A8 | 有可用的串口输出 | 主板 COM1 或 USB-TTL 转接 | 能看到 cunos 的串口输出（**这是唯一的调试通道，没有它不要开始**） |
| A9 | 能从 U 盘启动 | BIOS 支持 USB-HDD 启动 | 可以 |
| A10 | 有一台备用机器（或第二块盘） | — | 用于"卡死后继续查资料/烧盘" |
| A11 | 能物理断电 | — | 三落与死循环时唯一的恢复手段 |

**A4 的说明**：这一点容易被误解。SVM 是 64 位扩展的一部分，`EFER.SVME` 位于 EFER（一个 64 位 MSR）的 bit12。32 位内核完全可以读写 64 位 MSR（用 `rdmsr`/`wrmsr` 的两个 32 位寄存器），所以**32 位宿主可以跑 SVM**；但硬件是否暴露 `EFER.SVME` 的可写性，取决于具体实现。**必须在目标机上实测**：`wrmsr` 写 EFER bit12 后 `rdmsr` 读回，看是否为 1。

## 22.2 附录 B：常用 MSR 速查表

下表仅列本项目会用到的，**所有值与位定义必须与 AMD APM Vol.2 核对**。

| MSR | 地址 | 用途 | 我们的处理 |
|---|---|---|---|
| `TSC` | `0x00000010` | 时间戳计数 | 直通（配合 `TSC_OFFSET`） |
| `SYSENTER_CS` | `0x00000174` | 快速系统调用 | 直通（guest 自己设） |
| `SYSENTER_ESP` | `0x00000175` | 同上 | 直通 |
| `SYSENTER_EIP` | `0x00000176` | 同上 | 直通 |
| `MCG_CAP` | `0x00000179` | 机器检查能力 | 返回 0（无 MCA，避免 guest 尝试） |
| `APIC_BASE` | `0x000001BE` | 本地 APIC 基址 | 只读返回我们设定的值；阶段 4 前返回"APIC 不存在" |
| `PAT` | `0x00000277` | 页属性表 | 直通（单 guest 无害） |
| `MTRRdefType` | `0x000002FF` | MTRR 默认类型 | 返回 `0x800`（UC）或按需 |
| `EFER` | `0xC0000080` | 扩展特性（SVME/LME/NXE） | **必须拦截**：只许改 NXE，SVME/LME 拒绝 |
| `STAR` | `0xC0000081` | 系统调用段 | 直通 |
| `LSTAR` | `0xC0000082` | 系统调用入口 | 直通 |
| `CSTAR` | `0xC0000083` | 兼容模式入口 | 直通（返回值即可） |
| `SFMASK` | `0xC0000084` | 系统调用标志屏蔽 | 直通 |
| `FS_BASE` | `0xC0000100` | FS 段基址 | 直通（单 vCPU） |
| `GS_BASE` | `0xC0000101` | GS 段基址 | 直通 |
| `KERNELGS_BASE` | `0xC0000102` | 内核 GS 基址 | 直通 |
| `TSC_AUX` | `0xC0000103` | TSC 辅助（通常放 CPU 号） | 返回 0（单 vCPU） |
| `SYSCFG` | `0xC0010010` | 系统配置（含 SVM 锁定位） | **只读**（写即 `#GP`），防止 guest 改全局配置 |
| `HWCR` | `0xC0010015` | 硬件配置 | **只读**（写即 `#GP`） |
| `VM_CR` | `0xC0010114` | SVM 控制（`SVMDIS`/`LOCK`/`INIT_REDIRECT`） | **只读**（写即 `#GP`）；guest 不许碰虚拟化控制 |
| `VM_HSAVE_PA` | `0xC0010117` | 宿主状态保存区物理地址 | **只读**（写即 `#GP`）；这是宿主机密信息 |

**MSR 处理的统一原则**：默认 `#GP`，白名单放行。白名单越短越好——每放开一个 MSR 就多一个"guest 影响宿主"的可能。

## 22.6 附录 F：与 Intel VT-x 的对照（仅供理解，不实现）

| 概念 | AMD SVM | Intel VT-x |
|---|---|---|
| 控制结构 | VMCB（4KB，内存中） | VMCS（内存中，用 `VmPtrLd` 装载） |
| 进入 guest | `VMRUN`（一个操作数：VMCB 物理地址） | `VMLAUNCH`（首次）/ `VMRESUME` |
| 退出 | `#VMEXIT`（自动） | `VMEXIT`（自动） |
| 二级页表 | NPT（`nCR3`） | EPT（`EPT_POINTER`） |
| 二级缺页退出码 | `0x400` 类，信息在 `EXITINFO1` | `EXIT_REASON_EPT_VIOLATION`（48），信息在 `EXIT_QUALIFICATION` |
| TLB 标签 | ASID | VPID |
| 全局中断开关 | GIF（`STGI`/`CLGI`） | 无直接对应（用 `VMXON`/`VMXOFF` 与 interrupt-window） |
| 宿主状态保存 | `VMSAVE`/`VMLOAD` + `VM_HSAVE_PA` | `VMWRITE`/`VMREAD` + host-state 区 |
| 使能位 | `EFER.SVME` | `CR4.VMXE` |
| 超调用 | `VMMCALL` | `VMCALL` |
| 中断注入 | `V_IRQ` + `V_IRQ_VECTOR` | `VM_ENTRY_INTR_INFO_FIELD` |

**移植性设计建议**：把"`vcpu_enter_guest` / `vcpu_exit_info` / `npt_map` / `interrupt_inject`"这四个接口抽象出来，SVM 只是其中一个实现。这样将来做 VT-x 后端时，`vmexit.c` 与 `vdev_*.c` 一行都不用改。**这是低成本高回报的设计决策**，代价只是多一层函数指针。
