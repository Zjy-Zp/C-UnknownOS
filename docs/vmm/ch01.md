# 第 1 章 文档定位、读者与术语

## 1.1 本文要解决的问题

cunos 已经能做的事：从 Multiboot 引导、32 位保护模式、两级分页（无 PAE，4KB 页与 4MB 页混用）、用户态 ELF 加载、`int 0x80` 系统调用、协作式多进程（`PROC_MAX = 8`）、ext2 只读、ATA/AHCI 块设备、PCI 扫描、VBE 帧缓冲与窗口系统。

cunos 不能做的事：**在一台机器上同时拥有两个互不信任的特权域**。所有 `int 0x80` 背后的代码都在同一个 ring 0 里，任何用户程序触发的内核 bug 都能掀翻整机；也无法运行一个"没为 cunos 编译过"的操作系统二进制。

本文要回答的就是：**怎样用 SVM 硬件虚拟化，在 cunos 内核里再开一个世界**，让一个未经修改的 Debian i386 用户态在其中运行，而它的 `#GP`、死循环、非法端口访问都不会伤到宿主。

本文的边界必须写清楚，避免后续把设计文档当愿望清单：

| 属于本文范围 | 不属于本文范围 |
|---|---|
| SVM 硬件契约（VMCB/退出码/NPT）与它在 32 位宿主上的可用性 | Intel VT-x/VMX 的实现（第 22 章只给术语对照表） |
| cunos 内 VMM 的模块划分、数据结构、初始化流水线 | 完整 Debian 安装器、网络子系统、音频设备 |
| 阶段 1（自写 guest 打 hello）到阶段 5（Debian 用户态）的分级方案 | 迁移（live migration）、快照、嵌套虚拟化 |
| 阶段 2 的虚拟设备最小集（8250/8259/8254/PCI/ATA/VBE） | GPU 直通、SR-IOV、3D 加速 |
| 退出码处理策略与真机验证判据 | 安全隔离的形式化证明、侧信道防护 |

## 1.2 读者与前置知识

本文假定读者就是 cunos 的唯一维护者，具备以下知识，且**不需要**额外补课：

- 386 保护模式：GDT/LDT/IDT/TSS、段选择子与段描述符属性位、`iret` 的栈帧布局。
- 两级分页：PDE/PTE 格式、CR0.PG / CR3 / CR4.PSE、`invlpg`。
- 中断与异常：`int_regs` 现场、错误码压栈规则（cunos 的 `isr_default` 压 255 作为哨兵）。
- 块设备与文件系统：LBA 读写、ext2 inode 与间接块。

**不需要**的知识：Linux 内核内部结构（本文全程不引用 Linux 源码）、ACPI/AML 解释器、UEFI。

## 1.3 术语表

术语混乱是虚拟化设计文档最常见的失真源。下表给出本文的**唯一**用词，并标注常见误用。

| 术语 | 本文定义 | 常见误用（不要这样用） |
|---|---|---|
| VMM（Virtual Machine Monitor） | 直接操作 SVM 硬件、负责创建/运行/拦截 vCPU 的那部分代码，在 cunos 里就是 `vmm/` 目录 | 把整个"虚拟机"叫 VMM |
| hypervisor | 与 VMM 同义；本文只在讨论分类（Type-1/2）时用这个词 | 指代某个具体产品 |
| guest（客户机） | 运行在 VMCB 描述的执行环境里的代码，可以是一个裸 32 位程序，也可以是 Debian 内核 | 把"Debian"和"guest"混用（Debian 是 guest 里跑的一个 OS） |
| host（宿主） | cunos 内核自身，运行在 ring 0 且不在 VMCB 上下文中 | 把物理机叫 host |
| VMCB（Virtual Machine Control Block） | 4KB、必须 4KB 对齐的硬件结构，分 control area 与 state save area 两段，VMRUN/VMSAVE/VMLOAD 的操作对象 | 把它当作"软件里的 vm 结构体"（`vm_t` 是软件结构，VMCB 是硬件结构） |
| state save area | VMCB 的 `0x400–0xFFF` 段，保存 guest 的通用寄存器、段寄存器、CR/EFER/RIP/RSP/RFLAGS | 与 control area 混淆 |
| control area | VMCB 的 `0x000–0x3FF` 段，保存拦截位图、ASID、nCR3、退出信息 | 认为它也能存寄存器 |
| NPT（Nested Page Table） | AMD 的第二级地址翻译，把 guest 物理地址（GPA）翻成宿主物理地址（HPA） | 与 Intel 的 EPT 混称（架构不同，表项位定义不同） |
| GPA / HPA | guest physical address / host physical address；cunos 里必须严格区分，混一次就是一次静默越界读写 | 把 GPA 直接当地址解引用 |
| ASID（Address Space ID） | VMCB 里 32 位字段（有效位宽随 CPU 型号变化），用于给不同 guest 的 TLB 项打标签 | 认为 ASID 与宿主 CR3 的 PCID 是一回事（PCID 是 Intel 概念，AMD 无 PCID） |
| GIF（Global Interrupt Flag） | 一个**全局**开关：GIF=0 时物理中断（INTR/NMI/SMI）不会被递送给 guest，也不会打断 VMRUN 的执行流；由 `STGI`/`CLGI` 与 `#VMEXIT` 自动改写 | 与 RFLAGS.IF 混淆（IF 是 guest 自己的指令级开关） |
| #VMEXIT | 从 guest 陷入宿主的唯一事件；硬件恢复宿主上下文并**自动清零 GIF**，宿主从 `VMRUN` 的下一条指令继续执行 | 认为是"异常"，会有错误码压栈（不，它不压栈，退出原因在 VMCB 的 EXITCODE） |
| 退出码（EXITCODE） | control area 里 `0x070` 处的 64 位字段（低 32 位有效），标识本次退出的原因 | 当作返回值从 VMRUN 读出（VMRUN 没有返回值） |
| EXITINFO1 / EXITINFO2 | 控制区的两个 64 位辅助字段，语义随退出码而变（IOIO 时 1 是端口与方向，NPF 时 2 是出错的 GPA） | 混用两者语义 |
| 拦截（intercept） | control area 中的位图：某位置 1 表示对应事件必须退出给宿主 | 与"拦截端口范围"混淆（端口用 IOPM 位图，不是这个位图） |
| IOPM / MSRPM | 各 12KB 的位图，分别描述哪些端口/哪些 MSR 访问需要退出 | 认为 IOPM 一位对应一个端口（实际一位一个字节端口） |
| clean/dirty 位 | control area 里 `0x0C8`/`0x0CC` 附近的一组标记，告诉 VMRUN "哪些 state save 字段必须从 VMCB 装回 CPU、哪些可以沿用" | 认为是缓存一致性位 |
| VMRUN / VMLOAD / VMSAVE | `0F 01 D8` / `0F 01 DA` / `0F 01 DB`；VMRUN 用 EAX/RAX 传 VMCB 物理地址，切换 guest 上下文并开始执行 | 认为 VMRUN 会返回（它只在 #VMEXIT 后"看起来"返回） |
| HSAVE 页 | `VM_HSAVE_PA`（MSR `0xC0010117`）指向的 4KB 页，硬件在 VMRUN 时把宿主上下文存进去、在 #VMEXIT 时取回 | 认为可以用同一个 HSAVE 页并发跑多个 vCPU |
| shadow（影子） | 宿主维护的一份"客户机应该看到的设备状态"，用于遮盖硬件真实状态 | 与"NPT 影子页表"混淆（后者是软件模拟 MMU 的老方案，本文不用） |

## 1.4 两个写作约定

**约定一：不确定就必须说**。虚拟化文档最危险的错误不是漏写，而是把一个记错的偏移写得像真的一样。例如"asid 在 `0x058`"这句话如果错了，代码会在真机上以 `#GP` 或静默行为异常的形式失败，而调试成本极高。因此本文对每一个不掌握确定依据的数值都标 **【需核对】**，并在第 22.2 节给出可执行的核对方法（`offsetof` 断言 + QEMU/真机二分）。

**约定二：代码必须是能编译的形态**。全文代码按 cunos 现有风格书写：无 libc、无浮点、`u8/u16/u32/u64` 来自 `common.h`、内存分配只用 `pmm_alloc_page()` 与 `kmalloc()`、日志只用 `serial_puts/hex/dec`、内联汇编用 AT&T 语法（与 `boot.S`、`paging.c` 一致）。凡出现"省略号"，都会明确写出省略了什么。
