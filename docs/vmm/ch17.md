# 第 17 章 与 cunos 图形栈的集成

## 17.1 先明确现状：cunos 目前没有图形栈

第 7 章的模块清单里没有帧缓冲、没有显卡驱动。因此"把 guest 画面显示出来"这件事有两层，**必须分开做**，否则会把"虚拟机显示"和"写显卡驱动"混成一团：

| 层 | 内容 | 归属 |
|---|---|---|
| 宿主显示层 | 拿到一块线性帧缓冲（`fb_base` + `width/height/bpp/pitch`），能把像素写上去 | cunos 的基础设施（阶段 4 前置） |
| 客户机显示层 | 把 guest 的 VBE 帧缓冲内容搬到宿主帧缓冲（可能带缩放） | **VMM 的 `vdev_vbe.c`** |

如果 cunos 的启动协议（multiboot 或自研 bootloader）已经能拿到 VBE 模式信息（`framebuffer_addr/pitch/width/height/bpp`），第一层就是现成的；如果没有，阶段 4 的第一个任务是"在 bootloader 里设一个 1024×768×32 的线性帧缓冲并把参数传给内核"。**这件事在 VMM 之外**，本文只依赖它的结果：

```c
/* cunos 应提供的宿主显示接口（若尚不存在，需按此签名实现） */
typedef struct {
    u8 *base;        /* 线性帧缓冲虚拟地址（已映射到内核虚拟地址空间） */
    u32 width, height;
    u32 pitch;       /* 每行字节数，可能 > width*bpp/8 */
    u32 bpp;
} host_fb_t;

extern host_fb_t g_host_fb;
```

## 17.2 guest 的画面怎么出来：不要用 VBE BIOS

一个直觉方案是"给 guest 提供 `int 0x10` 的 VBE 功能（`0x4F00/0x4F01/0x4F02`）"，但那要求我们实现一套 VBE BIOS 表，而且 Debian 的 `vesafb` 依赖 `int 0x10` 返回的 `VbeInfoBlock` 与 `ModeInfoBlock`——**结构体长、字段多、容易做不全**。

更省事的方案：**让 guest 用 `bochs-drm` 驱动**。它的特点是：

- 通过 **PCI 设备**（vendor `0x1234`，device `0x1111`）识别，不需要任何 BIOS 调用；
- 通过 **IO 端口 `0x1CE/0x1CF`**（就是我们 13.7 已实现的 DISPI 接口）设置模式；
- 通过 **BAR0（MMIO）或线性帧缓冲地址** 直接写像素；
- Debian 的 i386 内核里 `CONFIG_DRM_BOCHS` 通常已内置（若为模块，需进 initrd）。

于是"guest 显示"变成：我们提供一个虚拟 PCI 显卡（`1234:1111`）+ DISPI 端口 + 一块 guest 物理地址上的帧缓冲 + 在宿主侧把这块内容合成到 `g_host_fb`。

```c
/* vdev_vbe 的合成：把 guest 帧缓冲（GPA 窗口）搬到宿主帧缓冲 */
void vbe_compose(vdev_t *d)
{
    vbe_t *v = d->priv;
    if (!(v->enable & 1) || !g_host_fb.base) return;
    if (v->bpp != 32 && v->bpp != 16) return;      /* 只支持 32/16bpp */

    u32 sx = v->xres ? (g_host_fb.width  / v->xres) : 1;
    u32 sy = v->yres ? (g_host_fb.height / v->yres) : 1;
    u32 scale = sx < sy ? sx : sy;                 /* 整数倍缩放，保持比例 */
    if (scale == 0) scale = 1;
    if (scale > 4)  scale = 4;                     /* 上限，避免过度放大 */

    u32 dw = v->xres * scale, dh = v->yres * scale;
    u32 ox = (g_host_fb.width  - dw) / 2;          /* letterbox 居中 */
    u32 oy = (g_host_fb.height - dh) / 2;

    u8 *src = (u8 *)ram_va(VBE_GPA_BASE);
    for (u32 y = 0; y < dh; y++) {
        u32 syy = y / scale;
        u8 *srow = src + (u64)syy * v->pitch;
        u32 *drow = (u32 *)(g_host_fb.base + (u64)(oy + y) * g_host_fb.pitch) + ox;
        for (u32 x = 0; x < dw; x++) {
            u32 sxx = x / scale;
            u32 px;
            if (v->bpp == 32) px = *(u32 *)(srow + sxx * 4);
            else              px = rgb565_to_rgb888(*(u16 *)(srow + sxx * 2));
            drow[x] = px;
        }
    }
}
```

**性能警告**：逐像素缩放在 1024×768 上是 78 万次循环，每次 `vbe_compose` 都要跑一遍，绝不能"每帧都做"。必须用脏矩形（17.5）。

## 17.3 双缓冲与抖动规避

直接把 guest 帧缓冲画到屏幕会看到"半帧撕裂"（guest 正在重绘的中间状态）。两种处理：

| 方案 | 做法 | 代价 |
|---|---|---|
| **脏矩形 + 定时合成** | guest 每次写帧缓冲产生 NPF 时记录脏页，`vbe_compose` 只处理脏页对应的显示区域，且按固定节拍（如 20Hz）合成 | 需要 NPF 上报，需要节拍 |
| **垂直同步** | 无（我们拿不到宿主的 vsync） | — |

实践方案：**脏页位图 + 20Hz 合成**。脏页位图用 1 bit / 4KB，8MB 帧缓冲 → 2048 位 = 256 字节，开销可忽略。

```c
/* ex_npf 命中帧缓冲时置位 */
static void vbe_mark_dirty(vbe_t *v, u32 gpa)
{
    u32 page = (gpa - VBE_GPA_BASE) >> 12;
    v->dirty[page >> 3] |= (u8)(1u << (page & 7));
    v->dirty_any = 1;
}
```

## 17.4 输入注入

键盘走 8042（13.8）。鼠标两条路：

- **PS/2 鼠标**（IRQ12，端口 `0x60`/`0x64` 的辅助通道）：Debian 内核有 `psmouse`，但坐标是相对位移，需要 guest 侧做指针加速逻辑，体验一般；
- **virtio-input**（PCI 设备）：协议明确（`EV_KEY`/`EV_REL`/`EV_ABS` 事件 8 字节结构），坐标绝对，但要 guest 有驱动（`virtio_input.ko` 一般在 initrd 里）。

阶段 4 建议：**键盘走 PS/2，鼠标走 PS/2 相对位移**（零驱动依赖），等阶段 5 再考虑 virtio-input。

坐标映射（宿主窗口坐标 → guest 像素坐标）必须与 17.2 的缩放一致：

```c
void vbe_inject_mouse(vdev_t *d, int wx, int wy)
{
    vbe_t *v = d->priv;
    u32 scale = vbe_current_scale(v);
    int gx = (wx - vbe_ox(v)) / (int)scale;
    int gy = (wy - vbe_oy(v)) / (int)scale;
    if (gx < 0 || gy < 0 || gx >= (int)v->xres || gy >= (int)v->yres) return;
    kbd_inject_mouse_delta(d->vm, gx - v->last_mx, gy - v->last_my);
    v->last_mx = gx; v->last_my = gy;
}
```

**这里有个陷阱**：缩放映射一旦算错，表现是"鼠标能看见但点不中按钮"，而不会报任何错误。建议在开发期画一个调试网格叠加（每 100 guest 像素一条线），一眼就能看出映射是否偏。

## 17.5 三种显示形态的取舍

| 形态 | 实现 | 优点 | 缺点 |
|---|---|---|---|
| **全屏独占** | 直接把 guest 帧缓冲铺满宿主屏 | 简单，性能最好 | 无法与 cunos 的 shell 共存；出问题只能重启 |
| **窗口化** | 宿主绘制一个矩形区域 + 边框，把 guest 内容缩放进去 | 可与 shell 共存，能一边看日志一边看画面 | 需要窗口系统（cunos 目前没有） |
| **"文本模式 + 串口"** | 不做图形，只把 guest 的 VGA 文本（0xB8000 的 80×25）转成字符流打到串口 | 零图形依赖，**阶段 2-3 的唯一可行方案** | 只能看文本 |

**结论：阶段 2-3 用"文本模式转字符 + 串口"，阶段 4 用"全屏独占 + 简单叠加"。** 窗口化必须等 cunos 有自己的窗口管理，不在本项目范围。
