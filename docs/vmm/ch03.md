# 第 3 章 为什么 cunos 要做 VMM：三条路线的量化对比

## 3.1 三条路线的定义

**路线 A（本文采纳）：内核内建 SVM VMM。** cunos 自己执行 `VMRUN`，自己处理 `#VMEXIT`，自己模拟设备，guest 可以是任意 i386 代码（含 Debian 内核）。

**路线 B：Linux ABI 兼容层。** 不写 hypervisor，而是让 cunos 直接加载并运行 Linux 的 ELF 二进制：实现一套与 Linux i386 兼容的系统调用号与语义、`/proc` `/sys` `/dev` 的假文件树、`ld.so` 与动态链接、`epoll`/`futex`/`io_uring` 等等。这条路线的本质是"把自己变成一个不完整的 Linux"。

**路线 C：宿主 QEMU 外包。** cunos 跑在 QEMU（或其它现成 hypervisor）里，需要跑 Debian 时由宿主侧的 QEMU 实例承担，cunos 只做串口/共享目录的搬运。本质是"承认自己没有虚拟化能力"。

## 3.2 对比表

下表是本文对三条路线的判断。表中"新增代码量"是**基于接口面宽度的估算**（依据列在表后），不是测量值。

| 维度 | A：内核内建 SVM VMM | B：Linux ABI 兼容层 | C：宿主 QEMU 外包 |
|---|---|---|---|
| 能跑什么 | 任意 i386 OS/裸程序（有驱动即可） | 只跑"编译过、且不用被兼容层遗漏的接口"的程序 | 能跑一切，但**不在 cunos 里跑** |
| 能力边界 | 受限于设备模型完整度与 NPT 实现 | 受限于 syscall/ABI 覆盖率，永远追不上内核演进 | 零能力增长，cunos 仍是单体玩具 |
| 不可逾越的墙 | 无（只是工作量问题）；单核 32 位宿主的性能上限 | 用户态程序一旦用 cunos 未实现的接口（`clone3`/`io_uring`/`userfaultfd`）立即失败；内核模块、`/proc` 语义、`setuid` 语义无法完全复刻 | "cunos 运行了 Debian"这句话永远不成立 |
| 新增代码量估算 | **6000–9000 行 C + 约 300 行汇编**（VMM 核心 ~2000，设备模型 ~3000，Debian 支持增量 ~2000） | **15000 行起，且无上限**（Linux i386 约 350+ 系统调用，加上 ELF 动态链接、线程、信号、网络协议栈） | **200–500 行胶水** |
| 对现有代码的复用 | 高：`paging.c` 提供页分配、`ext2.c`/`ata.c` 提供 rootfs、`vga.c`/`drm.c` 提供显示、`pci.c` 提供设备枚举范式 | 中：`elf.c` 可复用，其余几乎全部要新写 | 无（代码不参与） |
| 可验证性（真机现象） | **强**：串口打一行 `GUEST: hello` 就是成功；之后每一步都有可观察现象（退出码计数、屏幕字符、Debian 登录提示） | 弱：失败现象是"某个程序退出码 139/38"，难以定位是哪个 ABI 差异 | 无：验证的是 QEMU，不是 cunos |
| 失败模式 | 明确（`#VMEXIT` 退出码 + 卡死点可定位） | 模糊（ABI 语义偏差，症状千奇百怪） | 不适用 |
| 与"自研 OS"目标的一致性 | **高**：VMM 是 OS 能力的一部分，代码量可控且边界清晰 | 低：越写越像在重造 Linux | 零 |

**结论：选 A。** 理由不是"技术上更酷"，而是三条硬指标：

1. **工作量有上界**。A 的接口面是"硬件契约"（VMCB 字段 + 退出码 + 设备寄存器），这是封闭且可枚举的；B 的接口面是"Linux 用户态 ABI"，是开放且持续增长的。有上界的工作量才有交付可能。
2. **失败可定位**。A 的每一次失败都对应一个退出码或一个卡死的 RIP，能二分；B 的失败往往表现为"程序行为异常"，没有明确责任边界。
3. **复用率最高**。cunos 已经有分页、块设备、ext2、PCI、帧缓冲，这些都是 VMM 需要的"宿主侧基础设施"，而 A 恰好把它们全用上（第 7 章逐个点名）。

## 3.3 路线 A 的代价必须提前承认

选 A 不等于没有成本，下面三项是路线 A 的真实代价，写在这里是为了第 20 章的风险表有来源：

- **宿主内核 bug 面变大**：设备模型跑在 ring 0，任何越界都是全机崩溃。
- **调试手段缺失**：没有 gdb stub，没有符号表，只有串口和 `#VMEXIT` 计数。
- **单核 32 位性能天花板低**：guest 与宿主共享一个核，退出成本在微秒量级，Debian 的 boot 会明显比 KVM 慢（量级估算见第 19 章）。
