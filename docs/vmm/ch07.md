# 第 7 章 cunos 现有地基盘点

## 7.1 逐模块体检

VMM 不是一个"从零开始的孤儿模块"，它有相当一部分能力可以躺在现有代码上。下表逐个点名，并明确"能直接用 / 要改 / 缺"。

| 模块 | 能直接复用什么 | 必须改什么 | 对 VMM 最重要的缺口 |
|---|---|---|---|
| `paging.c` | `pmm_alloc_page()`（4KB 清零页）、`paging_map_page()`（建 4KB 映射并拆大页）、`paging_virt_to_phys()`、`invlpg` 封装 | ① `paging_map_page()` 的"已有页表"分支写成了 `g_pd[pdi] \|= 0x007`，应为 `g_cur_pd[pdi] \|= 0x007`（`fork` 后每进程独立页目录时才暴露）；② 需要导出 `paging_alloc_pt()` 供窗口映射复用 | 无"物理页回收到空闲链"的能力（只有 bump），VMM 的页表页与 guest 页一旦分配就不回收——对单 VM 场景可接受 |
| `pmm` 池边界 | `g_pmm_limit = max(kernel_end + 8MB, 32MB)` 且**硬上限 `0x03000000`（48MB）** | 无需改 | **这是 VMM 选址的依据**：`[0x03000000, ...)` 永远不会被 `pmm` 占用，可安全划为控制池与 guest RAM 池（见 8.5） |
| `mm.c`（COW） | `fork` 时的写时复制思路（多进程共享只读页，写时拷贝） | 需要把"COW 页表"抽象成"页所有权 + 引用计数"，因为 guest 页也要做 COW（快照/回滚，阶段 5） | 现无引用计数 API，需新增 `page_ref_t` |
| `proc.c` | 进程结构、4KB 内核栈、`int_regs` 现场保存/恢复、协作式 `switch` | vCPU 若作为"进程"运行，需要扩展：`proc_t` 增加 `is_vcpu` 标志与 `vmm_ctx` 指针；且 4KB 内核栈对退出处理偏紧（建议 vCPU 用独立 8KB 栈） | **没有内核线程**（这是阶段 3 的最大障碍，见 8.4） |
| `proc.c` 调度 | 协作式：只在 `int 0x80` 里切换，无抢占、无定时器 | 跑 guest 时宿主完全失去 CPU（一次 `VMRUN` 可能几十毫秒），要支持"抢占"必须靠 guest 主动退出（`hlt`/IO）或 PIT 注入 | 无抢占点注入机制 |
| `gdt.c` | GDT 布局：`0x08` 内核代码、`0x10` 内核数据、`0x18` 用户代码、`0x20` 用户数据、`0x28` TSS | **不要动宿主 GDT**。guest 的 GDT 必须建在 guest RAM 里，由 VMCB 的 `GDTR` 指向（GPA），由 NPT 翻译 | 无"在 guest 内存里构造 GDT/IDT"的工具函数（可在 `vmcb.c` 里补 20 行） |
| `idt.c` | `isr_table[]`、`isr_common` 汇编入口、`int_regs` 结构、`isr_default` 压 255 哨兵 | 需要在 VMM 初始化时**挂钩** `#GP`(13)/`#UD`(6)/`#PF`(14)，并让钩子先检查 `g_in_vmrun` | 无"钩子注册"机制，需加 `idt_set_handler(vec, fn)` |
| `syscall.c` | `int 0x80` 分发框架、`int_regs` 参数传递 | 新增 2–3 个系统调用供用户程序驱动 VM：`vmm_create`/`vmm_run`/`vmm_status`（阶段 3） | 无权限检查（任何用户程序都能创建 VM），阶段 3 需要限制为 root |
| `vfs.c` | 32 项 fd 表、`read/write/lseek` 抽象 | guest 的磁盘镜像作为一个普通文件打开 → 块后端天然可插拔（镜像在 ext2 上、在 ATA 盘上、在内存里都一样） | fd 是"字节流"，块设备需要"按 LBA 读写 512 字节"，建议新增 `blkdev_t` 抽象而不是硬套 fd |
| `ext2.c` | 只读 ext2（inode、间接块、目录遍历） | **Debian rootfs 可以直接是一个 ext2 镜像文件**，由宿主 `ext2.c` 解析后喂给 guest；也可让 guest 自己带驱动（阶段 4 用 virtio-blk 更省事） | 无写支持；guest 若要写盘，需 COW overlay（内存脏页表） |
| `ata.c` / `ahci.c` | `ata_read_sectors()` / AHCI 命令表提交 | 不需要改（VMM 复用它们读镜像） | 无写扇区封装（AHCI 写可用，ATA PIO 写未封装） |
| `pci.c` | 配置空间读写（`0xCF8/0xCFC`）、BAR 解析、`pci_map_mmio` | guest 看到的必须是**虚拟 PCI 总线**，不能直通宿主配置空间（否则 guest 会改宿主 BAR）。需自建一张"虚拟配置空间表" | 无设备枚举结果的结构化快照（需把扫描结果转成 `vdev_pci_t`） |
| `vga.c` / `drm.c` | 帧缓冲基址、分辨率、双缓冲、绘制原语、窗口系统 | guest 的 VBE 帧缓冲需要映射到一块独立内存（影子帧缓冲），再由宿主"搬运"到窗口 | 无"外部像素源"接口，需加 `drm_blit_window(win, src, w, h, pitch)` |
| `keyboard` / `mouse` | 轮询式输入 | 需要把宿主键值翻译成 guest 的 8042 扫描码 / PS2 鼠标包 | 无扫描码表（需自建 60 项查表） |
| `elf.c` | ELF32 加载 | **不能用于 guest**（guest 有自己的 MMU 与页表，不能走宿主 `paging_map_user_range`）；可用于"把 bzImage 解压后放进 guest RAM" | guest 侧需要独立的 ELF/PE/bzImage 解析，且写的是 GPA 不是 VA |
| `shell` | 命令分发 | 新增命令 `vm`（创建/运行/统计），是阶段 1-2 的**唯一入口** | 无"阻塞式长任务"的交互设计（`vm run` 会占住 shell 直到 guest 退出） |

## 7.2 三个必须提前解决的"地基裂缝"

上面表格里有两处不是"缺功能"，而是**会直接坑死 VMM 的现有缺陷**，必须在阶段 0 修掉：

**裂缝一：`paging_map_page()` 的 `g_pd` / `g_cur_pd` 混用。**

```c
/* 现状（paging.c） */
} else {
    g_pd[pdi] |= 0x007;          /* ✗ 写的是"初始页目录"，不是"当前页目录" */
}
```

在单进程阶段无害（两者相同）。一旦 `fork` 出第二个页目录，`g_cur_pd` 指向新页目录，而这个分支改的是 `g_pd` ——VMM 的窗口映射恰好会大量命中这个分支（同一 4MB 块内连续映射多个页），后果是**窗口只映射上了第一页，后续页的 PTE 写进了一个没人用的页表**。症状极隐蔽：读 guest 内存时前 4KB 正常，之后全是 0 或随机值。

修法（一行）：`g_cur_pd[pdi] |= 0x007;`

**裂缝二：`paging_map_mmio_4m()` 会摧毁窗口。**

```c
g_cur_pd[pdi] = a | 0x09Bu;      /* 直接覆盖 PDE，丢弃原有 4KB 页表 */
```

如果对 `0xDFC00000–0xE7FFFFFF`（控制窗口与 RAM 窗口）所在区域调用它，窗口映射会被整块替换成 4MB 大页，指向**物理地址 == 虚拟地址**的位置——也就是 guest 内存窗口失效，宿主读到的是自己内核的数据。

规矩：**窗口区域永不调用 `paging_map_mmio_4m()`**。在 `vmm_map_window()` 里加一条断言把这条规矩变成运行时错误。

**裂缝三：无 `panic()` 与无 `free()`。**

VMM 需要"出错就停住并说清楚"，而现在只能 `serial_puts` 后死循环。建议加：

```c
void vmm_panic(const char *why, u32 a, u32 b)
{
    __asm__ volatile("cli");
    serial_puts("\n=== VMM PANIC ===\n");
    serial_puts(why);
    serial_puts("\na=0x"); serial_hex(a);
    serial_puts(" b=0x"); serial_hex(b);
    serial_putc('\n');
    for (;;) __asm__ volatile("hlt");
}
```

至于 `free()`：VMM 的页分配（控制池、guest 页）在单 VM 生命周期内只增不减，**不需要 free**。这是一处刻意的简化，写进设计里比事后发现"没人回收"要好。
