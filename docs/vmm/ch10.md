# 第 10 章 初始化流水线

## 10.1 流水线总览

```
vmm_init()                      宿主全局，一次
  ├─ svm_probe()                CPUID 探测        ─┐
  ├─ svm_enable()               EFER.SVME         ─┤ 失败 → 打印原因 + 返回 -1
  ├─ svm_hsave_alloc()          VM_HSAVE_PA       ─┘
  ├─ vmm_map_window(ctl)        控制窗口
  ├─ vmm_map_window(ram)        RAM 窗口
  └─ vmm_stats_init()           统计清零

vm_create(name, ram_size)       每台 VM
  ├─ 校验 ram_size（2MB 对齐、≤128MB、≤实际可用内存）
  ├─ 分配 iopm(12KB) / msrpm(12KB)
  ├─ npt_build()                NPT 铺 RAM
  ├─ vdev_* 全部 init()         设备注册
  └─ vcpu_create()              VMCB + HSAVE + guest 初始上下文

vcpu_run(vcpu)                  主循环（第 11.5 节）
```

## 10.2 每一步的失败分支

失败分支必须"**能打印、能返回、不留半个对象**"。下表是本文规定的行为：

| 步骤 | 可能的失败 | 判据 | 处理 |
|---|---|---|---|
| `svm_probe` | 无扩展 CPUID / 无 SVM 位 / 无 NPT | 见 4.2 代码 | 打印 `SVM: ...`（含 CPUID 原值），返回 `-ENODEV`；**不改任何状态** |
| `svm_enable` | `VM_CR.SVMDIS=1` / EFER 写不进 | 见 4.3 代码 | 打印 `SVM: disabled by firmware`，返回 `-EPERM`。此路径**意味着必须换机器/换固件设置**，不可软件绕过 |
| `svm_hsave_alloc` | 控制池不足 | `vmm_ctl_alloc_page()==0` | 返回 `-ENOMEM` |
| `vmm_map_window` | `paging_map_page` 失败（pmm 耗尽） | 返回 <0 | 打印失败的虚拟地址，返回 `-ENOMEM`。**此时已建的映射不回滚**（无 free 能力），因此窗口映射必须放在 `pmm` 尚有富裕的早期执行 |
| `vm_create` | ram_size 非法 / 控制池不足 | 校验函数 | 返回 `-EINVAL` / `-ENOMEM` |
| `npt_build` | 表页分配失败 | 同上 | 返回 `-ENOMEM`，`vm->state = DEAD` |
| `vdev_init` | 端口/MMIO 范围重叠 | 冲突检测 | 打印两个设备名与冲突范围，返回 `-EBUSY`。**必须实现这个检测**：两个设备抢同一端口会导致"读到的值总是另一个设备的"，极难查 |
| `vcpu_create` | VMCB/HSAVE 页不足 | 同上 | 返回 `-ENOMEM` |
| `vcpu_run` | VMRUN 失败（EFER/VMCB/对齐） | `g_in_vmrun` + 宿主 `#GP` | `vmm_panic`，打印 VMCB 物理地址与关键字段 |
| 主循环 | 未知退出码 | 见 5.4 兜底策略 | `state = FAULTED`，返回 `-EIO` |

## 10.3 `vm_create()` 实现

```c
static vm_t g_vms[VMM_MAX_VMS];
static vcpu_t g_vcpus[VMM_MAX_VCPUS];
static u32 g_vm_cnt, g_vcpu_cnt;

vm_t *vm_create(const char *name, u32 ram_size)
{
    if (g_vm_cnt >= VMM_MAX_VMS) { serial_puts("VM: too many vms\n"); return 0; }
    if (!ram_size || (ram_size & 0x1FFFFF) || ram_size > VMM_RAM_MAX) {
        serial_puts("VM: bad ram size\n"); return 0;
    }
    if (ram_size > vmm_ram_available()) {         /* 由 multiboot mem_upper 推导 */
        serial_puts("VM: ram exceeds physical memory\n"); return 0;
    }

    vm_t *vm = &g_vms[g_vm_cnt];
    memset(vm, 0, sizeof(*vm));
    vm->id = g_vm_cnt;
    strncpy16(vm->name, name);
    vm->ram_gpa_base = 0;
    vm->ram_size = ram_size;

    /* IOPM：12KB = 3 页（64K 个端口 / 8 位每字节 = 8KB，硬件要求按 3 页给），
     * 全 1 = 全部拦截，后续逐个端口清位开放。
     * MSRPM：同样 12KB，全 1 = 全部拦截。
     * ctl_alloc_pages(n) 是连续 n 次 bump 分配，控制池天然连续，故返回首地址即可。 */
    vm->iopm_pa = ctl_alloc_pages(3);
    if (!vm->iopm_pa) goto nomem;
    memset(ctl_va(vm->iopm_pa), 0xFF, 3 * PAGE_SIZE);

    vm->msrpm_pa = ctl_alloc_pages(3);
    if (!vm->msrpm_pa) goto nomem;
    memset(ctl_va(vm->msrpm_pa), 0xFF, 3 * PAGE_SIZE);

    if (npt_build(&vm->npt, ram_size) < 0) goto nomem;
    if (vdev_init_all(vm) < 0) goto nomem;
    if (vcpu_create(vm) < 0) goto nomem;

    vm->state = VM_STATE_READY;
    g_vm_cnt++;
    return vm;

nomem:
    vm->state = VM_STATE_DEAD;
    serial_puts("VM: create failed (control pool exhausted)\n");
    return 0;
}
```

> 关于 IOPM/MSRPM 的页数：端口空间是 64K 个，按位图每端口 1 位需要 8KB；但硬件规定这块位图区域按 **3 页（12KB）** 提供，第三页是为 MSR 空间与对齐保留的。**只给 8KB 的实现在某些 CPU 上会让 VMRUN 读到未初始化内存，表现为随机行为**——因此一律按 3 页分配。【需核对：APM 对 IOPM/MSRPM 区域大小的表述】

## 10.4 guest 初始上下文：把 16 位实模式世界"造"出来

阶段 1 的 hello guest 是 16 位实模式代码，从 `0x7C00` 开始（传统引导扇区位置）。构造它需要九个字段：

```c
/* 段属性常数（见 4.5.2 的 attrib 位定义） */
#define SEG_ATTR_CODE16   0x009Bu   /* type=1010 可执行可读, S=1, DPL0, P=1, D=0（16 位）, G=1 */
#define SEG_ATTR_DATA16   0x0093u   /* type=0010 可读写,   S=1, DPL0, P=1, D=0, G=1 */
#define SEG_ATTR_CODE32   0x00C9Bu  /* 32 位代码段（D=1） */
#define SEG_ATTR_DATA32   0x00C93u  /* 32 位数据段 */

int vcpu_init_real16(vcpu_t *vc, u32 entry /* = 0x7C00 */)
{
    u8 *v = vc->vmcb;

    /* 1) 段寄存器：全部 base=0, limit=0xFFFF, 16 位属性 */
    vmcb_set_seg(v, VMCB_OFF_CS, 0x0000, SEG_ATTR_CODE16, 0xFFFF, 0);
    vmcb_set_seg(v, VMCB_OFF_DS, 0x0000, SEG_ATTR_DATA16, 0xFFFF, 0);
    vmcb_set_seg(v, VMCB_OFF_ES, 0x0000, SEG_ATTR_DATA16, 0xFFFF, 0);
    vmcb_set_seg(v, VMCB_OFF_SS, 0x0000, SEG_ATTR_DATA16, 0xFFFF, 0);
    vmcb_set_seg(v, VMCB_OFF_FS, 0x0000, SEG_ATTR_DATA16, 0xFFFF, 0);
    vmcb_set_seg(v, VMCB_OFF_GS, 0x0000, SEG_ATTR_DATA16, 0xFFFF, 0);

    /* 2) GDTR/IDTR：实模式不使用，limit=0、base=0 */
    vmcb_wr32(v, VMCB_OFF_GDTR + 4, 0);
    vmcb_wr32(v, VMCB_OFF_GDTR + 8, 0);
    vmcb_wr32(v, VMCB_OFF_IDTR + 4, 0);
    vmcb_wr32(v, VMCB_OFF_IDTR + 8, 0);

    /* 3) TR/LDTR：见下方警告，必须合法 */
    vmcb_set_seg(v, VMCB_OFF_TR, 0x0000, 0x008Bu, 0xFFFF, 0);   /* 16 位 TSS 可用 */
    vmcb_set_seg(v, VMCB_OFF_LDTR, 0x0000, 0x0082u, 0xFFFF, 0);

    /* 4) 控制寄存器：实模式 CR0.PE=0；ET 位由硬件固定，写 0x10 更贴近真实复位值 */
    vmcb_wr64(v, VMCB_OFF_CR0, 0x00000010ull);
    vmcb_wr64(v, VMCB_OFF_CR4, 0x00000000ull);
    vmcb_wr64(v, VMCB_OFF_CR3, 0x00000000ull);   /* 实模式不用页表 */
    vmcb_wr64(v, VMCB_OFF_CR2, 0x00000000ull);
    vmcb_wr64(v, VMCB_OFF_EFER, 0x00000000ull);  /* 无 SVME / 无 LME / 无 NXE */

    /* 5) 指令指针与栈 */
    vmcb_wr64(v, VMCB_OFF_RIP, entry);
    vmcb_wr64(v, VMCB_OFF_RSP, 0x7C00);          /* 栈向下长，从 0x7C00 开始 */
    vmcb_wr64(v, VMCB_OFF_RFLAGS, 0x00000002ull);/* IF=0（宿主 IF 也是 0，语义一致）*/

    /* 6) CPL */
    *(u8 *)(v + VMCB_OFF_CPL) = 0;

    /* 7) ASID 与 TLB 控制 */
    vmcb_wr32(v, VMCB_OFF_ASID, 1);
    *(u8 *)(v + VMCB_OFF_TLB_CTL) = 0;

    /* 8) 二级翻译 */
    vmcb_wr64(v, VMCB_OFF_NCR3, (u64)vc->vm->npt.ncr3_pa);

    /* 9) 拦截配置（阶段 1 最小集） */
    vmcb_wr16(v, VMCB_OFF_IEXCP, 0);                  /* 不拦异常（先让 guest 自己的问题暴露） */
    vmcb_wr32(v, VMCB_OFF_INTERCEPT, INT_HLT | INT_SHUTDOWN);
    vmcb_wr64(v, VMCB_OFF_IOPM_PA, (u64)vc->vm->iopm_pa);
    vmcb_wr64(v, VMCB_OFF_MSRPM_PA, (u64)vc->vm->msrpm_pa);

    vc->state = VCPU_STATE_READY;
    return 0;
}
```

关于 TR 的警告：**很多实现"看起来能跑"是因为 TR selector 恰好为 0 且 guest 从不做任务切换；但在部分 CPU 上，VMRUN 要求 TR 的 selector/attrib 与 limit 自洽，否则 `VMRUN` 直接失败或 guest 第一次访问栈时就 `#GP`。**【需核对：APM 对 VMCB.TR 有效性的要求】本文的做法是"无论如何都填一个合法的 16 位 TSS 描述符属性"，成本为零、风险归零。

## 10.5 实模式 guest 起点的三个坑

1. **`0x7C00` 必须在 guest RAM 里，且 NPT 已铺上。** 我们的 `npt_build` 把整个 RAM 用 2MB 大页铺开，`0x7C00` 在第一个 2MB 内，天然可达。
2. **guest 的代码必须先被写进去。** 用 `memcpy(ram_va(0x7C00), boot_bin, boot_len)`，其中 `boot_bin` 是宿主编译期嵌入的 512 字节引导扇区（第 11.1 节）。
3. **不要试图让 guest 从 `0xFFFFFFF0`（复位向量）开始。** 那是真实复位流程，需要 BIOS 在 `0xFFFF0000` 有影子代码段、需要 CS base=0xFFFF0000，对最小闭环毫无必要。直接给 `RIP=0x7C00`、`CS base=0` 是"跳过 BIOS"的关键简化，也是第 15 章"自写 32 位直引导 loader"的技术基础。
