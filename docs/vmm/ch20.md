# 第 20 章 风险清单与缓解措施

| # | 风险 | 概率 | 影响 | 缓解措施 |
|---|---|---|---|---|
| R1 | 目标真机 BIOS 未开启 SVM（`VM_CR.SVMDIS=1` 或 CPUID 不出 SVM 位） | 中 | 阻断（无法验证） | 阶段 0 第一件事就是 `svm_probe` 并把结果打串口；提前准备 2 台候选机器；检查 BIOS 里 "SVM Mode"/"Virtualization" 开关 |
| R2 | 目标机是 Intel（无 SVM） | 中 | 阻断 | 同上；文档中并列给出 Intel VT-x 对照（附录 F），未来可移植但不是本范围 |
| R3 | NPT 层级假设错误（实际 4 级/折叠级别与预期不同） | 高 | 阶段 1 就卡住 | 11.3 的 5 分钟实验；`npt.c` 全部索引逻辑集中在一个 `npt_indices()` 函数里，改一处即可 |
| R4 | VMCB 字段偏移/位定义记错 | 高 | 症状诡异（乱跳、随机崩） | **强制自检**：`vmcb_selftest()` 对每个字段"写特征值 → 读回 → 比对"，启动时跑一遍；所有不确定项在代码里标注 `/* NEED-APM-CHECK */` |
| R5 | VMRUN 失败导致三落，无任何输出 | 高 | 无法定位 | 11.4 的 `#GP`/`#UD` 钩子；VMCB 预置兜底 IDT（18.7） |
| R6 | Debian 只有 686-pae 内核，未开 PAE 支持 | 高 | 阶段 3 卡在 "requires pae" | CPUID 上报 PAE；确认 guest 的 PAE 与宿主无关（16.1） |
| R7 | initrd 缺块设备驱动，`No working init found` | 高 | 阶段 3 卡住 | 先走 ATA 模拟（内核自带 `ata_piix`）；或按 16.2 注入 `.ko` |
| R8 | 性能不可接受（ATA PIO 逐字节） | 高 | 阶段 4 无法使用 | 19.3 手段二（字符串 IO 批量）+ 19.4（virtio） |
| R9 | 串口日志拖慢启动数十倍 | 高 | 误判为"性能不行" | 19.7 的三条优化 |
| R10 | guest 死循环导致宿主失去响应 | 中 | 需硬重启 | 19.5 退出预算；**在实现退出预算之前不要跑未验证的 guest** |
| R11 | 宿主内存不足（guest RAM 与 pmm 冲突） | 中 | 数据损坏 | `vm_create` 里断言 `ram_pa >= 0x03000000` 且 `ram_end <= mem_upper`；`pmm` 硬上限不动 |
| R12 | 只读 ext2 镜像被 guest 写坏 | 中 | 宿主文件损坏 | 阶段 3 只读 + 假写成功；COW overlay 后再开写 |
| R13 | 代码量失控（预估 4800 行 → 实际 2 倍） | 高 | 项目延期 | 严格按阶段交付；每阶段"能演示"才算完，不留"半成品模块" |
| R14 | 无调试器（无 gdb stub） | 高 | 排障效率低 | 18 章全套工具（trace 环形、dump、stat、单步）；**这些工具要最先写，不是最后写** |
| R15 | 不同 AMD 家族 VMCB 字段差异（如新家族扩展字段） | 中 | 换机器就崩 | 只用 APM 定义的基础字段；不碰扩展字段；`vmcb_selftest` 在目标机跑 |
| R16 | 时间漂移（guest 时钟比真实快/慢） | 中 | 超时误判、日志时间戳错乱 | 校准 `g_tsc_per_ns`；用 `TSC_OFFSET` 做偏移修正；定期与宿主 PIT 对齐 |
| R17 | 宿主中断全关期间过长（`STGI`/`CLGI` 用错） | 中 | 丢中断、串口丢字符 | 默认 `STGI` 常开；只在 `VMRUN` 那一小段 `CLGI`；**不要**整段 `vm_run` 都关着 |
